# 게임 퀄리티 전담팀 (오너 11-19: "게임 하나하나 퀄리티도 퀄리티 전담팀에서 신경 써줘야 해")

목표: 허브의 모든 게임(registry 기준)을 하나씩 **'다시 하고 싶은' 수준**으로 끌어올린다. 신작을 만들지 않는다. 있는 게임의 결을 깎는다.
장부: [quality/ledger.md](./quality/ledger.md) — 게임당 1행, 8항목 0~3점.

## 1. 교대 (ROTA.md)
- 03시(UTC 18)·15시(UTC 06) KST, 하루 2교대. 교대마다 **게임 3개**(장부에서 '미점검' → 합계 최저 순). 다른 교대가 여는 PR의 게임·파일은 피한다(`gh pr list`).
- 역할은 서브에이전트로 나눈다(worktree 격리): **플레이 테스터**(실제로 해 보고 점수·증거), **수정 담당**(게임당 PR 1개), **독립 리뷰어**(수정 담당이 아닌 에이전트가 diff와 전후 캡처를 보고 놓침·부족·과함을 지적). 리뷰 지적을 반영한 뒤 머지한다.

## 2. 점검 8항목 (각 0~3)
1. **첫 10초**: 설명 없이 무엇을 할지 알 수 있나. 첫 입력까지 걸리는 시간.
2. **조작감**: 입력 지연, 오터치, 드래그·탭 판정, 손가락에 가려지는 곳.
3. **손맛**: 누를 때·맞출 때·실패할 때의 반응(움직임·소리·진동). 성공의 쾌감이 있나.
4. **읽기 쉬움**: 대비, 글자 크기, 색만으로 구분하는 곳, 정보 과다.
5. **난이도 곡선**: 첫 판 성공 가능성, 3판째의 긴장, 막힘·지루함.
6. **다시 하고 싶음**: 결과 화면이 "한 판 더"를 부르나(최고 기록·차이·다음 목표).
7. **모바일 390**: 화면 꽉 참, 스크롤 갇힘, 가로 스크롤, safe-area, 회전.
8. **세계관**: 노을 정원 틀과 어울리나(네온·픽셀 폰트·이모지 아이콘 잔재, 결과 화면 마스코트 반응).

## 3. 절차 (게임 1개)
1. Playwright 390×844 터치 에뮬 + 1440으로 **실제로 3판 이상** 한다. 첫 화면·플레이 중·결과 캡처, 콘솔 에러, 성능(긴 프레임) 기록.
2. 8항목 점수와 근거(캡처·수치) → 고칠 것 우선순위 3개(가장 점수를 많이 올리는 것부터).
3. 수정 PR(게임당 1개, M 이하): 게임 로직을 건드리면 엔진 테스트 추가·통과. 전후 캡처를 PR에 붙인다.
4. 독립 리뷰 → 반영 → 전체 `pnpm test && pnpm typecheck` 초록 → squash 머지 → 배포 확인(라이브 URL 200 + 실제 화면).
5. 장부 행 갱신(점수·날짜·PR) — 같은 PR.

## 4. 하지 않는 것
- 게임 규칙·점수 체계를 바꿔 기존 기록을 무효로 만드는 것(바꿔야 하면 HANDOFF에 오너 결정 요청으로 남긴다).
- slug·공유 URL 변경, 게임 화면 안 광고, 리더보드 데이터 조작.
- 사이트 전체 리디자인(별도 PR 큐 — 리디자인 팀). 퀄리티팀은 게임 안쪽만.

## 5. UX 친화성 체크리스트 (오너 11-20 "모든 부분에 있어 사용자 친화적으로")
게임·페이지·공통 컴포넌트 PR마다 본다. **자동** 표시는 e2e·스크립트가 떨어뜨린다. 점검 도구: `node scripts/ux-audit.mjs http://localhost:<포트> [/경로…]`(390 터치, JSON).
1. **누르는 영역 44×44 이상** — 보이는 크기가 작아야 하면 `.hit-44`(누르는 영역만 확장). **자동**: `e2e/bottom-sheet.spec.ts` '공통 컴포넌트 누르는 영역'(elementFromPoint로 실제 범위)·시트 안 전부, ux-audit `small`.
2. **모달은 공통 `BottomSheet` 하나로** — 손잡이 끌어 닫기(25%·튕김)·손잡이 탭/Enter·배경 탭·Esc·뒤로 가기·닫기 버튼이 같은 길. 새 모달을 손으로 만들지 않는다(판 위 `absolute` 덮개 — GameOverlay·Simon Ready·Zero Hour Paused — 는 모달이 아니라 예외). 768 이상 카드는 손잡이가 숨으니 내용에 닫기 버튼을 둔다. **자동**: bottom-sheet.spec(짧게→복귀, 길게→닫힘, 튕김→닫힘, 안쪽 스크롤과 충돌 없음, 배경 탭·Esc·뒤로 가기).
3. **모달 뒤 배경이 스크롤되지 않고, 닫히면 원래 자리** — **자동**: bottom-sheet.spec '배경 스크롤 잠금'(휠·배경 스와이프).
4. **포커스**: 열면 안으로, Tab 가둠, 닫히면 연 버튼으로. 연 버튼을 모달이 열린 동안 지우지 않는다(지우면 포커스가 body로 샌다). **자동**: bottom-sheet.spec '포커스가 돌아온다'.
5. **모션 줄이기면 즉시** — 등장·퇴장·복귀 모두. **자동**: bottom-sheet.spec '모션 줄이기'.
6. **입력칸 글자 16px 이상**(iOS 포커스 확대 방지), viewport meta로 확대를 막지 않는다. **자동**: ux-audit `zoomInputs`·`meta`, 시트 안은 bottom-sheet.spec.
7. **누르면 바로 반응**: 누름 모양(`btn-press`·`garden-jelly`), 기다리는 동안 문구·`aria-busy`('Making your card…', 제출 '…'), 끝나면 결과 문구(aria-live). 검사 불가 사유: '느낌'은 화면을 봐야 한다 — 2장 3번 손맛 점검에 포함.
8. **실수는 되돌릴 수 있게**: 판을 지우는 버튼(New game·Reset·End round)은 확인 또는 Undo. 검사 불가 사유: 게임마다 뜻이 달라 장부 'UX 친화성' 절로 본다.
9. **스크롤 갇힘 없음**: 판 위 `touch-action:none`은 판 크기만(위·아래 띠는 페이지 스크롤 — PlayZone). ux-audit `touchNone`으로 확인.
10. **길게 누르기·호버에만 기대지 않기**: 같은 동작을 탭·버튼으로도. 검사 불가 사유: 입력 설계 문제라 플레이 테스트(첫 10초)에서 본다.
