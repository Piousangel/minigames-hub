# 게임 퀄리티 전담팀 (오너 11-19: "게임 하나하나 퀄리티도 퀄리티 전담팀에서 신경 써줘야 해")

목표: 허브의 모든 게임(registry 기준)을 하나씩 **'다시 하고 싶은' 수준**으로 끌어올린다. 신작을 만들지 않는다. 있는 게임의 결을 깎는다.
장부: [quality/ledger.md](./quality/ledger.md) — 게임당 1행, 8항목 0~3점.

## 1. 교대 (ROTA.md)
- 03시(UTC 18)·15시(UTC 06) KST, 하루 2교대. 교대마다 **게임 3개**(장부에서 '미점검' → 합계 최저 순). 다른 교대가 여는 PR의 게임·파일은 피한다(`gh pr list`).
- 역할은 서브에이전트로 나눈다(worktree 격리): **플레이 테스터**(실제로 해 보고 점수·증거), **수정 담당**(게임당 PR 1개), **독립 리뷰어**(수정 담당이 아닌 에이전트가 diff와 전후 캡처를 보고 놓침·부족·과함을 지적). 리뷰 지적을 반영한 뒤 머지한다.

## 2. 점검 8항목 (각 0~3)
1. **첫 10초**: 설명 없이 무엇을 할지 알 수 있나. 첫 입력까지 걸리는 시간.
2. **조작감**: 입력 지연, 오터치, 드래그·탭 판정, 손가락에 가려지는 곳.
3. **손맛**: 누를 때·맞출 때·실패할 때의 반응(움직임·소리·진동). 성공의 쾌감이 있나.
4. **읽기 쉬움**: 대비, 글자 크기, 색만으로 구분하는 곳, 정보 과다.
5. **난이도 곡선**: 첫 판 성공 가능성, 3판째의 긴장, 막힘·지루함.
6. **다시 하고 싶음**: 결과 화면이 "한 판 더"를 부르나(최고 기록·차이·다음 목표).
7. **모바일 390**: 화면 꽉 참, 스크롤 갇힘, 가로 스크롤, safe-area, 회전.
8. **세계관**: 노을 정원 틀과 어울리나(네온·픽셀 폰트·이모지 아이콘 잔재, 결과 화면 마스코트 반응).

## 3. 절차 (게임 1개)
1. Playwright 390×844 터치 에뮬 + 1440으로 **실제로 3판 이상** 한다. 첫 화면·플레이 중·결과 캡처, 콘솔 에러, 성능(긴 프레임) 기록.
2. 8항목 점수와 근거(캡처·수치) → 고칠 것 우선순위 3개(가장 점수를 많이 올리는 것부터).
3. 수정 PR(게임당 1개, M 이하): 게임 로직을 건드리면 엔진 테스트 추가·통과. 전후 캡처를 PR에 붙인다.
4. 독립 리뷰 → 반영 → 전체 `pnpm test && pnpm typecheck` 초록 → squash 머지 → 배포 확인(라이브 URL 200 + 실제 화면).
5. 장부 행 갱신(점수·날짜·PR) — 같은 PR.

## 4. 하지 않는 것
- 게임 규칙·점수 체계를 바꿔 기존 기록을 무효로 만드는 것(바꿔야 하면 HANDOFF에 오너 결정 요청으로 남긴다).
- slug·공유 URL 변경, 게임 화면 안 광고, 리더보드 데이터 조작.
- 사이트 전체 리디자인(별도 PR 큐 — 리디자인 팀). 퀄리티팀은 게임 안쪽만.
