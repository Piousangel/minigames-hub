# 오너 질문: 미니게임을 토스 인앱(앱인토스)에 넣을 수 있나 (2026-11-17)

## 질문 원문 요지
- 미니게임을 앱으로 만들고, 기획을 뾰족하게 다듬어서 토스 인앱에 넣을 수 있나?
- 서버·DB를 붙여도 된다. 불필요한 기능과 중복 기능은 빼고, 진짜 필요한 것만 남긴다.
- 팀 내부에서 충분히 회의한 뒤 답해도 된다.

## 사전 조사 (메인 세션, 11-17)
- 앱인토스는 설치 없이 실행되는 **웹게임을 우선 지원**한다. 지금 엔진을 재사용할 수 있고, 네이티브 앱을 새로 만들 필요는 없다.
- **사업자 없이도 등록할 수 있다.** 다만 이 경우 수익화 기능(광고, 인앱결제)과 토스 로그인을 쓸 수 없다. 돈을 벌려면 오너의 개인사업자 등록이 사실상 필요하다.
- **게임은 등급분류 증빙이 필수다.** 구글·애플·원스토어의 자체등급분류를 거친 스토어 URL, 등급분류 사업자명, 등급분류일자를 낸다. 등록자명이 사업자명과 다르면 반려된다. 이 정보를 누락하면 등급미필 게임물로 간주되어 행정조치 대상이 된다.
- 출처: toss.im/apps-in-toss/blog/game_rating_classification, toss.im/apps-in-toss/blog/self-rated_game_distribution, developers-apps-in-toss.toss.im

## 팀이 답할 것 (다음 회의 안건, 결론은 메일 첫 단락으로 보고)
1. **뾰족한 한 줄 정의**: 토스 사용자가 하루에 한 번 열 이유는 무엇인가. 예시는 "30초 데일리 한 판 + 친구 순위"이고, 정답이 아니다.
2. **남길 것과 뺄 것**: 웹 포털의 80여 개 게임 가운데 토스판에 넣을 3~5개를 고른다. 1순위는 오리지널 게임이고, 상표·원작 의존이 있는 게임은 제외한다. SEO 페이지, 가이드, 중복 장르는 뺀다.
3. **서버·DB 범위**: 기존 D1 리더보드를 재사용할지, 토스 로그인 기반 사용자와 친구 순위를 둘지 정한다. 비용과 장애 설계도 함께 적는다.
4. **수익 모델**: 보상형 광고와 인앱결제 가운데 무엇을 쓸지, 웹 포털 AdSense와 충돌하는지 본다.
5. **오너가 해야 할 일 목록**: 사업자 등록, 등급분류 경로(원스토어 또는 구글플레이), 앱인토스 콘솔 가입.
6. **일정**: 큰 기능 슬롯(화·목) 몇 번으로 MVP를 만들 수 있나. 웹 포털 작업과 어떻게 병행하나.
