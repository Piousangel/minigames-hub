# 토스 미니게임 허브 (앱인토스) — 팀이 자체 힘으로 운영한다 (오너 결정 2026-11-17)

## 결정
- 토스에는 **게임 하나가 아니라 "미니게임 허브" 앱**으로 들어간다. 게임을 계속 추가해 사람이 다시 올 이유(오늘의 퍼즐, 친구 랭킹, 모으는 캐릭터)를 만든다.
- **오너 없이 팀이 개발·검증·배포·운영한다.** 오너가 해야 하는 일은 아래 "오너 전용"뿐이다.
- 첫 앱은 이미 콘솔에 만들어져 있다: appName `recoil-puzzle`(변경 불가, 사용자에게는 '반동 퍼즐'로 보임). 이름을 허브로 바꾸는 건 콘솔에서 앱 이름(수정 가능)만 바꾼다. appName은 그대로 둔다.

## 현재 상태 (toss/ 폴더)
- Vite+React 정적 번들. 웹 포털의 순수 엔진(`@/lib/games/*/engine.ts`)을 그대로 재사용한다. UI만 토스용으로 새로 만든다.
- 구현됨: Recoil 한 판, 오늘의 퍼즐(KST), 연습, 캐릭터 5종(`src/characters.ts`)과 해금, 토스 SDK 래퍼(`src/toss.ts`: 식별키·저장소·리더보드·햅틱·뒤로가기), 마스코트 스프링 애니메이션(`src/Mascot.tsx`).
- 비주얼: 캐릭터 전신 포즈(idle/aim/fire/happy/dizzy). **톤은 '우주 도토리 숲'(docs/design/toss-recoil/direction/R1~R3) 목표 시안**으로 가는 중. 게임 오브젝트·UI는 아직 기본 스타일이라 목표 시안 수준으로 올리는 것이 1순위 작업이다.

## 허브 구조 (팀이 만든다)
1. `toss/src/games/<slug>/` 단위로 게임을 넣는다. 각 게임은 `{ id, title, tagline, Component, engine 재사용 여부, 오늘의 시드 함수, 리더보드 점수 정의 }`를 레지스트리에 등록한다.
2. 허브 홈: 오늘의 퍼즐 카드(게임 여러 개 중 날짜로 순환), 최근 한 게임, 내 캐릭터, 연속 기록. 첫 10초 안에 한 판을 시작할 수 있어야 한다.
3. 공통 셸: 결과 시트, 소리 토글, 도움말, 종료 확인, 저장(`store.ts`)을 게임이 공유한다.
4. 게임 선정 기준(웹 포털 게임 중): 한 손 조작, 첫 판 10초 안에 규칙이 보임, 한 판 30~90초, 매일 새 판이 가능(시드), 우리 오리지널(상표 이슈 없음). 조준형 Recoil은 허브 안의 한 게임으로 두고, **탭형 반동 게임(쏘면 반동으로 튀어 오름)**을 첫 화면 대표 후보로 시제품을 만든다.

## 팀이 자체로 하는 일
- 개발: PR → CI(타입 검사·빌드·.ait 번들 생성)가 통과하면 머지.
- 배포: main 머지 시 `.github/workflows/toss-build.yml`이 .ait를 만들고, `AIT_API_KEY` 시크릿이 있으면 `ait deploy`로 콘솔에 업로드한다(테스트 번들. **출시 버튼은 오너 승인 후 누른다**).
- QA: Playwright 모바일 폭으로 홈→한 판→결과를 확인하고 캡처를 PR에 남긴다. 캡처 없이 완료라고 쓰지 않는다.
- 운영: 콘솔의 지표(방문, 재방문, 광고, 리더보드)와 반려 사유를 매일 회의에서 읽고 backlog에 반영한다. 지표는 앱인토스 '핵심 지표' 화면에서 오너가 주 1회 캡처를 `docs/daily/metrics/toss/`에 올리거나, API가 열리면 자동화한다.
- 마케팅: 허브 캐릭터가 마케팅 소재다. 캐릭터 소개·제작기·오늘의 퍼즐 결과 공유를 Bluesky/Threads/블로그로 낸다.

## 성장 규칙
`docs/team/GROWTH.md`를 따른다. 특히 **허브는 매주 새 게임 1개 또는 새 캐릭터 1개**를 추가하고, 같은 형식의 게임을 연속으로 만들지 않는다.

## 품질 기준 (오너 지적: 11-17 "퀄리티가 떨어진다", "너무 부자연스럽다")
- 비주얼은 캐릭터만 고급이고 나머지가 기본 UI면 불합격이다. 배경·오브젝트·UI·연출이 한 톤이어야 한다.
- 캐릭터는 전신 포즈 이미지를 스프링으로 움직인다. 부위 조립 리깅은 쓰지 않는다(팔이 몸에서 떨어져 부자연스러웠다).
- 이미지 생성은 Gemini 나노바나나(스크립트와 프롬프트는 docs/design/toss-recoil/에 기록). 배경색 키잉은 옷 색과 겹치지 않는 색을 고른다(민트 옷은 마젠타, 마젠타 옷은 초록).
- 눈에 보이는 워터마크는 없다(API 이미지). 최종 에셋은 필요하면 벡터로 다시 그려 용량과 화질을 맞춘다.

## 등급분류 (출시 전 필수, 가장 큰 병목)
- 게임은 등급분류 증빙이 있어야 검토가 통과된다. 허브에 게임이 여러 개면 **게임마다 등급 증빙이 필요한지 앱인토스에 확인**해야 한다(채널톡 문의는 오너). 확인 전까지 허브 1호 출시는 **게임 1개로 시작**한다.
- 경로: 원스토어 또는 Microsoft Store로 자체등급(IARC) → 콘솔의 게임 등급분류 탭에 스토어 URL·사업자명·일자 입력. 등록자명은 사업자명 "행복가게"와 같아야 한다. 원스토어 'AI 게임' 분류 경로는 반려된 사례가 있다.

## 오너 전용 (팀이 할 수 없는 것)
1. 정산 정보 검토 결과 메일 확인(콘솔 → 내 정보).
2. 콘솔 → 키에서 **API 키 발급** → GitHub 시크릿 `AIT_API_KEY` 등록(`! pbpaste | gh secret set AIT_API_KEY --repo Piousangel/minigames-hub`).
3. 등급분류 계정 가입(원스토어 개발자, 무료)과 문의 채널 소통.
4. 토스 앱에서 QR 테스트 후 피드백.
5. **출시 버튼과 검토 요청 최종 클릭**.
