# 디자이너 방향 문서 (2026-11-19): 우리 사이트만의 시각·모션 언어

방법: 390x844로 /plop-landing, /acorn-hop, /slime-slide 직접 확인, draw.ts·fx.ts·GamePlopLanding.tsx 코드 확인, public/art 27개 목록, GEMINI.md 비용 규칙, 조사 C, 이전 혹평(4.5/10) 반영. 저장소 파일은 수정하지 않음.
한계: 모션 타이밍(ms)은 코드 수치와 경험칙 기준 제안이며 프레임 단위 실측은 안 했다. 아래 수치는 "시작값"이고 시안에서 조정한다. 효과음은 파일을 못 들어 톤만 제안.

## 0. 약점부터 (현재 상태 진단)

1. **세 게임이 같은 세계로 안 보인다.** 직접 본 결과 타이틀 색이 게임마다 다르다(Acorn 노랑 네온, Slime 시안 네온, Plop 핑크 네온). 배경도 Acorn=보라 밤 + 보름달, Slime=노을, Plop=새벽/노을. 캐릭터는 말랑이(Plop·Slime)와 다람쥐(Acorn)가 서로 만나지 않는다. 공통점은 "갈색 윤곽 + 크림 pill"인데 Slime은 그것도 안 지킨다(보드에 갈색 프레임 없음, HUD가 "Ink 100%" 일반 텍스트, 탭이 윤곽선 직사각형).
2. **44px 규격이 이미 깨져 있다.** Plop 코드의 버튼은 `h-10`(40px), 모드 토글은 `h-9`(36px), 사운드·새로고침 버튼 min-w-10. 44px 규칙을 세우려면 기존부터 고쳐야 한다.
3. **"우리만의 것"이 아직 에셋 한 벌(노을+갈색 윤곽)뿐이다.** 모션 언어는 없다. 파티클은 범용(spark/confetti/star/ring)이고 인게임 폰트는 `sans-serif` 시스템 폰트라 기기마다 다르다. 보상 연출은 한 프레임 폭발이라 "연속 서사"가 없다(이전 리뷰 ⑤ 4.5/10).
4. **사이트 크롬(상단 바, 픽셀 로고, 어두운 배경)이 게임 세계와 충돌.** 게임 안은 파스텔 노을인데 바깥은 CRT 느낌 다크 + 픽셀 폰트다. 두 세계가 한 화면에 있다. 이건 사이트 전체 정체성 문제라 내 범위를 넘고, 결정으로 올린다(요구 5번).
5. **내 제안의 위험**: 모션을 풍성하게 설계하면 Canvas 2D + 모바일 저사양에서 프레임이 떨어진다. 그래서 모든 연출에 "움직임 줄이기" 대체(파티클 1/3, 흔들림 제거, 색·크기 변화만)를 같이 정의한다. 또 아래 에셋 수치는 Gemini 일관성 실패(재생성)를 50% 가산했다.

### 1-2. 선·그림자·모서리
- **윤곽선 3종**: 큰 오브젝트(섬·카드) 4px, 중간(버튼·pill) 3px, 작은 것(아이콘·별) 2px. 항상 ink 색. 선 끝은 round.
- **그림자는 "아래로 단단히 떨어진 갈색 판"**: 모든 면에 `0 3px 0 ink-deep`(카드는 5px). 블러 그림자 금지(= 범용 UI 느낌). 눌리면 그림자 0 + translateY 3px.
- 모서리 radius: 카드 16, 버튼 pill(full), 칩 12. 직각 금지.
- 안쪽 하이라이트: 카드 상단 안쪽에 `inset 0 0 0 2px #fbeccc`(현 HUD와 동일).
- 글꼴: 본문·숫자는 **둥근 헤비 산세리프 1종으로 고정**(후보: Baloo 2 또는 Fredoka, Google Fonts 800 굵기, 한글은 Jua 또는 Gaegu 대신 시스템 fallback 허용 여부는 결정 요청). 캔버스 텍스트도 `document.fonts` 로드 후 같은 폰트. 사이트 크롬의 픽셀 폰트는 "로고 전용"으로 축소.

### 1-4. 모션 타이밍 토큰
| 토큰 | 값 | 설명 |
|---|---|---|
| t-input | 0~80ms | 입력 → 시각 반응(눌림, 웅크림). 80ms 넘으면 "씹힘". 소리도 같은 프레임. |
| t-anticipate | 80~140ms | 캐릭터 예비 동작(스쿼시). 이전 리뷰의 "선 놓고 500ms 정지"는 150ms 이하로. |
| t-micro | 120~200ms | 버튼 눌림·pill 등장 |
| t-reward-s | 400ms | 도토리·점수 +N 팝 |
| t-reward-m | 650ms | perfect·영역 확정 |
| t-reward-l | 900ms | 스테이지 클리어·별 확정(상한. 넘으면 지루함, 스킵 가능해야 함) |
| t-ui | 220~320ms | 화면 전환·카드 슬라이드 |
| t-hold | 80~130ms | 히트스톱(강타만. 약타 0) |

이징 곡선(CSS cubic-bezier 값 고정):
- **ease-pop** (튀어나옴, 보상 등장): `cubic-bezier(0.34, 1.56, 0.64, 1)` (오버슈트 약 10%)
- **ease-out-soft** (대부분의 이동·번짐): `cubic-bezier(0.22, 1, 0.36, 1)`
- **ease-in-snap** (사라짐·빨려 들어감): `cubic-bezier(0.5, 0, 0.75, 0)`
- **spring-jelly** (캐릭터 스쿼시 복귀): 코드 스프링 stiffness 220 / damping 12 / mass 1 (한 번 오버슈트 후 정착, 약 350ms).
- 선형 보간 금지(현 도토리 팝이 선형이라 싸구려로 보였다).
- 겹침 규칙: 한 번의 타격에 반응 4~6개를 80~100ms 안에 겹친다(조사 C 경험칙). 단 보상 연출 전체는 t-reward-l을 넘지 않는다.

### 1-5. 효과음 톤 (코드 합성음 전제, 샘플을 못 쓰는 환경 가정)
- 한 문장: **"젤리 속에서 물방울이 튀고, 도토리 껍질이 톡 하는, 따뜻한 목관 톤"**. 전자음·8비트 금지(사이트 크롬이 이미 레트로라 게임 안은 대비를 준다).
- 입력: 짧은 `pop`(sine 520→260Hz 60ms). 착지: 낮은 `plop`(sine 220→110Hz + 노이즈 20ms).
- 보상: 마림바풍 3음 상승 (C5-E5-G5, 각 90ms, triangle). 연속 보상은 반음씩 상승(현 도토리 피치 상승 유지).
- 실패: 풀 죽는 "뽀옹" 하강(sine 330→120Hz 250ms), 사이렌·버저 금지.
- 소리는 기본 끔 가능, 음소거 아이콘은 모든 게임에서 같은 위치(오른쪽 상단 pill 줄).

### 1-6. 컴포넌트 규격 (모두 터치 영역 44x44 이상)
- **버튼**: 높이 44, 최소폭 44, pill, 3px ink 윤곽, 하단 3px 그림자. 주(sun-gold) / 보조(cream) / 위험(coral). 시각 크기가 작아도 히트 영역은 padding으로 44 확보.
- **모드 토글(Daily/Practice)**: 전체 높이 44, 각 세그먼트 최소폭 88.
- **HUD pill 줄**: 보드 안 상단 8px 안쪽, 높이 44(현재 약 40). 좌 = 핵심 수치, 중앙 = 보조(콤보·시간대), 우 = 상태. 폰트 18/12.
- **결과 카드**: 보드를 가리지 않는 하단 시트(높이 화면의 55%), cream 면 + 4px ink 윤곽 + 상단 둥근 모서리 24, 안에 ①큰 수치(48px, bloom-coral) ②별 3칸 ③부제(내 순위/베스트) ④버튼 2개(공유 = sun-gold, 다시 = cream). 공유 이미지는 같은 카드를 캔버스로 그린 것.
- **안전 여백**: 좌우 16px 거터, 하단 노치 safe-area 포함.

### 1-7. 다른 사이트가 베낄 수 없는 것 3가지 (베끼기 어려운 이유 포함)
1. **"노을은 지지 않는다 + 시간대가 점수로 흐른다"**: 판이 진행될수록 하늘이 새벽→낮→노을→밤으로 천천히 변하고, 이것이 난이도·스테이지 구조와 묶여 있다(Plop은 이미 tint 3단계). 세계가 같은 시계를 공유한다. 베끼려면 배경을 바꾸는 게 아니라 게임 구조를 바꿔야 한다. 단 한계: 알아채는 사람만 알아챈다.
2. **"젤리 물리가 UI에도 있다"**: 버튼·카드·HUD도 스프링으로 눌리고 되돌아온다(spring-jelly 토큰을 CSS와 캔버스에 공통 적용). 캐릭터가 UI 위로 지나가면 UI가 찌그러진다(결과 카드에 말랑이가 걸터앉는다 등). 일반 사이트는 정적 UI 위에 게임을 올린다. 단 한계: 구현 비용과 성능 부담이 있고, 사진 한 장으로는 전달이 안 되며 영상으로만 보인다.
3. **"하루가 하나의 정원이 된다"(일일 결과 = 내가 꽃을 피운 지도)**: 오늘 푼 스테이지·판마다 섬에 꽃·덩굴이 한 송이씩 피고, 공유 이미지는 숫자가 아니라 **그 날의 내 정원 스냅샷**이다. 점수 숫자 공유(Wordle 정사각형 이모지)와 구분된다. 단 한계: Wordle식 공유 문화를 이기려면 "스냅샷이 예쁘다"를 첫 공유 이미지에서 증명해야 한다(예쁘지 않으면 가장 먼저 무너지는 항목).

## 2. 말랑 미끄럼길: 순차 해금 화면 + 스테이지 시각 차별화

### 2-1. 설계 원칙(조사 B 반영)
- 해금은 **이전 스테이지 클리어만**으로(별 총량 요구 없음, 막힘 마찰 제거). 별 1~3은 재도전 동기. 별 기준은 잉크 잔량(코드에 이미 존재하는 값 활용): 클리어 1별 / 잉크 50% 이상 2별 / 도토리 3개 전부 3별(스테이지 정책은 PM과 합의 필요).
- 지도는 **세로 스크롤 한 장(꽃길)**, 아래에서 위로 올라간다(낮은 시간대→높은 시간대가 아니라 "아침에서 밤으로" 하루가 흐른다). 한 화면(390x844)에 4~5개 노드가 보이게.
- 길은 **꽃길**(끊어진 섬 사이를 꽃잎·징검돌 점선이 잇는 형태). 잠긴 구간은 길이 안개(구름)로 덮여 있고 꽃봉오리가 닫혀 있다. 열린 구간은 꽃이 피어 있다.
- 오늘 합산 점수는 상단 sticky pill(항상 보임). 스테이지 노드 옆에는 각 별.

### 2-3. 해금 연출 "다음 섬이 열린다" (총 1.6s, 스킵 가능, 클리어 결과 카드 직후)
타임라인(클리어 순간 = 0ms):
| ms | 연출 |
|---|---|
| 0~80 | 히트스톱 80ms + 말랑이 happy로 교체 (t-hold) |
| 80~700 | 별 1→2→3 순서로 카드에서 지도 노드로 날아가 박힌다(각 120ms 간격, ease-pop, 마림바 3음) |
| 700~1000 | 카메라가 지도를 위로 스크롤(ease-out-soft)해 다음 노드를 중앙에 |
| 1000~1500 | 다음 섬 위의 안개가 노을빛 한 줄기로 갈라지며 걷힌다(구름 sprite 2개를 양옆으로 밀어냄 = 기존 cloud-a/b 재사용), 닫힌 꽃봉오리가 "딸깍" 열린다 |
| 1100~1600 | 현재 노드와 다음 노드 사이 꽃길 점선 위로 꽃잎이 한 송이씩 피며 이어진다(왼쪽→오른쪽 80ms 간격) |
| 1600 | 말랑이가 새 노드로 점프해 착지(소프트 스쿼시), 주 버튼이 "스테이지 N ▶"로 바뀌며 pill이 한 번 부푼다 |
- 움직임 줄이기: 날아가는 별 → 즉시 채움, 안개 → 투명도 페이드 200ms, 점프 → 순간 이동 + 글로우.
- 오늘 합산 점수 pill의 숫자는 이 연출 중 카운트 업(480ms, ease-out-soft).
- 약점: 스테이지 클리어마다 1.6s는 반복되면 길다. **첫 클리어 해금만 풀 연출, 이미 열린 스테이지 재클리어는 0.6s 축약**.

### 2-4. 스테이지 시각 차별화 (10스테이지 안, 오너 "8~12" 범위)
원칙: 스테이지 하나 = **시간대 + 섬 + 소품 1개 + 기믹 시각 단서 1개**. 기믹 단서는 "플레이 전에 보여야" 한다(이전 리뷰의 "충돌 전엔 위험이 안 보임" 대응). 기믹별 공통 규칙: **위험 = 빨강 윤곽 점멸, 이로운 것 = 노랑 글로우, 움직이는 것 = 궤도 점선**.

| # | 시간대 | 섬/소품 | 기믹(이름은 PM 몫) | 시각 단서 |
|---|---|---|---|---|
| 1 | 아침 | 작은 풀 섬 + 민들레 | 기본(선 하나) | 손가락 고스트 선 데모 1회 |
| 2 | 아침 | 풀 섬 + 버섯 | 독꽃 2개 | 빨강 윤곽 점멸 + 꽃잎 떨림 |
| 3 | 낮 | 구름 섬 + 풍차 | 움직이는 발판 | 발판 궤도 점선, 발판 끝에 화살 |
| 4 | 낮 | 바위 섬 + 폭포 | 좁은 틈 | 틈 양쪽 바위 윤곽 두껍게, 틈에 노란 글로우 |
| 5 | 노을 | 꽃밭 섬 + 깃발 | 튕기는 벽 | 벽이 버섯 쿠션 모양, 평소 1.5s 주기로 살짝 눌렸다 폄 |
| 6 | 노을 | 큰 섬 + 등대 | 스위치 | 스위치 = 노란 버튼 꽃, 닫힌 문 = 덩굴 문(스위치 누르면 덩굴이 풀림) |
| 7 | 저녁(노을→밤 전환) | 징검돌 섬들 | 지나가면 사라지는 길 | 징검돌에 균열 선 |
| 8 | 밤 | 달 아래 섬 + 반딧불 | 어둠 구간(시야 제한) | 반딧불 3마리가 길 힌트(따라가면 정답 쪽) |
| 9 | 밤 | 별똥별 섬 | 낙하하는 별 | 별 그림자가 먼저 땅에 표시 |
| 10 | 새벽(마지막) | 구름 위 큰 정원 | 앞 기믹 2개 조합 | 앞에서 본 단서가 모두 한 화면에 |
- 시간대 흐름 = 아침→낮→노을→밤→새벽으로 한 바퀴. 하루 합산 10스테이지를 끝내면 "하루가 한 바퀴 돌았다"는 서사(독자 서사 1번 근거).
- **현재 상태 평가**: 이전 리뷰 ⑦ 스테이지 차별화 3/10. 4개 스테이지가 같은 배경에 오브젝트 위치만 바뀌었다. 위 표처럼 시간대·섬 외형·소품이 다 바뀌어야 비로소 "스테이지 차이"로 읽힌다.
- 접근성: 위험/이로움은 색 외에 **형태(가시·불꽃 모양 윤곽, 노랑은 별 모양 반짝임)**로도 구분.

## 3. 신작 (가칭 「꽃담」 — "벽바둑" 이름은 쓰지 않는다) 비주얼·모션

이름 주의: 조사 A-8에 따라 "벽바둑/Wall Go" 사용 금지. 가칭 **꽃담(Flower Fence)**. 영어 사이트 표기는 별도 결정(결정 요청 2번에 포함).

### 3-1. 판과 말
- 판 = 5x5 풀 섬(위에서 약 20도 기울어 본 쿼터뷰), 모서리가 섬 절벽·구름으로 끊김. 칸은 풀 타일 두 톤(leaf / #8ad07a) 체크.
- 말: **말랑이(내) 2마리 vs 토리(상대) 2마리**. 토리는 이미 에셋 5종(idle/aim/fire/happy/dizzy)이 있어 신규 캐릭터가 필요 없다. 세 게임의 두 캐릭터가 한 판에서 만나는 것이 세계관 통일의 핵심 장면.
- 벽의 두 종류(소유 표시): 내 벽 = **덩굴**(leaf 색 + 꽃봉오리), 상대 벽 = **바위/도토리 껍질 울타리**(ink 윤곽, 황토색). 색약도 구분되는 형태 차이.
- 영역 색: 내 영역 = 따뜻한 노을 주황(#ffb070 55% 알파), 상대 영역 = 연보라(#b79ad9 55%). 점수 칸 수는 칸 위 작은 꽃 아이콘 개수(숫자는 요약줄에만).

### 3-2. 벽이 "자라는" 연출 (벽 하나 = 선 하나)
벽 세우기 입력(선 탭) 순간부터:
| ms | 덩굴(내 벽) | 바위(상대 벽) |
|---|---|---|
| 0 | 탭한 선이 흰 점선으로 미리보기, 탭 즉시(≤80ms) 선이 한 번 눌림 | 동일 |
| 0~120 | 끝점 2곳에서 새싹 시작 | 끝점에 흙먼지 2점 |
| 120~420 | 선을 따라 덩굴이 양끝에서 중앙으로 자라나며 잎이 번갈아 나옴(ease-out-soft, 길이 따라 stroke-dash 애니메이션) | 바위 조각 3~4개가 위에서 떨어져 선에 정렬(각 60ms 간격, 착지마다 4px 흔들림) |
| 420~650 | 중앙에서 꽃봉오리 하나가 ease-pop으로 부풀며 펼쳐짐 | 맨 위 바위에 도토리 모자 얹힘 |
- 총 650ms(t-reward-m). 벽은 영구라 이 한 번의 비중이 크다. 연타로 지루해지지 않게 **두 번째 벽부터 단축 450ms**(AI 턴은 항상 450ms).
- 규칙 힌트: 막힌 선(설치 불가)은 탭하면 빨강 점멸 + 220ms 흔들림 + 이유 말풍선("말이 완전히 갇혀요" 등).

### 3-3. 영역이 노을빛으로 번지는 연출
영역이 닫히는 순간(마지막 벽이 맞물림):
1. 0~80ms: 히트스톱 + 닫힌 경계 덩굴이 한 번 반짝(흰 하이라이트가 경계를 따라 달림)
2. 80~600ms: 말이 있는 칸에서 **노을색이 원형 파동으로 칸 단위 번짐**(칸 간 40ms 간격 지연, 중심에서 바깥으로, ease-out-soft). 닫힌 칸에서 꽃이 하나씩 핀다.
3. 200~700ms: 칸 수 숫자가 +N 점프 카운트(칸마다 마림바 음이 반음씩 올라감).
4. 영역 안 말랑이가 부풀어(스케일 1→1.18, spring-jelly) 만족한 표정(happy)으로. 상대 영역도 같은 방식, 보라색 + 토리 happy.
- 큰 영역(6칸 이상)이면 "노을 번짐"이 판 전체 하늘 색조까지 약간 따뜻해짐(하늘 틴트 +10%, 600ms). 한 판 진행 = 하늘이 점점 노을로 → 마지막에 영역 비율이 높은 쪽 색이 하늘을 차지한다(핵심 시그니처, 공유 이미지에 넣을 것).

### 3-4. 말랑이·토리의 역할
- 말랑이는 **플레이어 말이자 감정 표시기**: 선택 시 호흡 빨라짐(주기 1.6s→0.8s), 이동 시 스쿼시-스트레치 + 도착 스쿼시, 갇히면 눈물방울 + 가라앉음(scaleY 0.9, dizzy→sad), 큰 영역을 먹으면 부푼다.
- 토리는 AI 말: 이동은 도토리 껍질을 타듯 통통 튀는 대각선 점프, 벽을 놓을 때 도토리 총(tori-fire) 포즈 1프레임 → 벽 생성. **상대가 생각 중일 때 토리가 턱을 괴는 모션(코드로 헬멧 기울임 3도)** 으로 AI 대기 시간(300~600ms)을 연출로 흡수.
- 약점/주의: 토리가 "총을 쏜다"는 기존 에셋은 벽 세우기와 의미가 다르다. 에셋 재사용을 위해 도토리 던지기로 해석한다. 폭력적으로 보이지 않게 탄환 = 도토리.

### 3-5. 타격감 순간 5개 (타이밍 ms)
| # | 순간 | 구성 | 총 시간 |
|---|---|---|---|
| 1 | **벽 뿌리내림**(벽 확정) | 선 눌림 0ms → 덩굴/바위 성장 → 끝 4px 화면 흔들림 1회(약, 60ms) + `thunk`음(sine 140→70Hz 90ms) | 650ms |

## 4. 세 게임의 세계관 통일안 + 공통 요소

### 4-1. 통일 방법: "같은 정원 섬의 세 구역"
| 구역 | 게임 | 위치 | 시간대(고정 팔레트 변형) | 주인공 |
|---|---|---|---|---|
| 섬 앞마당(착지장) | Plop Landing | 섬 지표 수평 | 새벽~노을(지금처럼 진행) | 말랑이 |
| 높은 나무(수직 구역) | Acorn Hop | 위로 오르는 하늘 | **노을~밤으로 통일**(현재 보라 밤 + 보름달 단독 → 노을에서 시작해 높이에 따라 밤으로: 같은 하늘을 공유) | 토리 |
| 징검 개울(선 구역) | Slime Slide | 섬 사이 바다 | 위 2-4 시간대 순환 | 말랑이 |
- **같은 하늘의 규칙**: 세 게임 모두 sky-top/sky-mid/sky-sea 토큰을 쓰고, 시간대는 게임 진행에 따라 변한다(Plop은 이미 구현, Acorn은 높이, Slime은 스테이지 번호).
- **카메오 규칙**: 각 게임 배경에 다른 게임 캐릭터의 작은 흔적을 숨긴다. Acorn 배경 구름 사이에 말랑이 실루엣이 한 번 지나감, Plop 섬 한쪽에 도토리 더미, Slime 스테이지 5 깃발에 토리 헬멧. 탭하면 소리 한 번(이스터에그, 반복 방문 이유). 에셋 신규 0장(기존 스프라이트 축소·실루엣 처리).
- **공통 프레임**: 모든 보드는 4px ink 윤곽 + 5px 아래 그림자 + radius 16(Plop 코드와 동일). Slime의 `border-white/15` 프레임을 이것으로 교체.
- **사이트 타이틀 색 통일**: 세 게임 h1을 같은 크림색 + 코랄 외곽(게임별 네온 색 폐기). 게임을 구분하는 건 색이 아니라 구역(배경)이다.
- **효과음 모티프**: 세 게임의 보상음 = 같은 3음 모티프(C-E-G), 악기만 다르게(말랑=마림바, 다람쥐=짧은 현 뜯음, 선 긋기=종).

### 4-2. 홈의 공통 요소
- 세 게임 카드를 **같은 정원 지도 한 장**에 섬 세 개로 배치(홈 상단 "오늘의 정원"): 오늘 플레이한 게임의 섬엔 꽃이 피어 있고 안 한 섬엔 봉오리. 3개 모두 피면 노을이 한 단계 더 짙어짐 + 가벼운 연출(연속 방문 이유).
- 카드 4요소 공통: ①구역 아이콘(섬 그림) ②게임명 ③오늘 상태 꽃 3칸(미플레이/플레이/최고기록 갱신) ④"오늘 N명" 소사회적 증거. 높이 약 112, 터치 영역 전체 카드.
- 한계: 세 게임밖에 없을 때만 성립하는 구조. 게임이 10개 이상으로 늘면 지도 한 장으론 안 된다(신작·다른 게임 편입 시 규칙 필요, 지금은 3~4개만 "정원 섬"으로 승격하고 나머지는 기존 목록).

### 4-3. 결과 카드 공통 요소
상단→하단: ① 게임 구역 아이콘 + 시간대 라벨 ② 큰 수치(48px, coral, 카운트 업 480ms) ③ 별/꽃 3칸(순차 채움 120ms 간격) ④ 한 줄 평(말랑이/토리 말풍선, 3종 이상) ⑤ 내 순위/베스트(NEW BEST는 sun-gold pill) ⑥ 버튼: 공유(sun-gold) · 다시(cream) 44px. 공유 이미지 = 카드 + 오늘의 정원 스냅샷(섬에 핀 꽃들) + 날짜 + 도메인.
- 현재 Plop 결과 오버레이는 이 구조에 가깝지만 **보드 위 중앙에 뜨고 말풍선·별 칸이 없다**. Slime은 "다음 스테이지" 버튼 하나뿐이어서 가장 먼 거리가 있다.

## 디자이너가 팀에 요구하는 결정 5개

1. **사이트 크롬 정리 여부**: 상단 바의 CRT/픽셀 폰트·어두운 배경을 게임 세계(노을 정원)와 맞출지, 게임 안 세계만 통일하고 크롬은 두는지. (제안: h1·버튼·pill은 노을 정원 토큰으로, 로고 폰트만 유지.) 이 결정이 안 나면 "같은 세계" 연출은 반쪽이다.
2. **신작 이름과 영문 표기**: "벽바둑/Wall Go/Devil's Plan" 계열 단어를 제목·설명·SEO에서 완전히 배제하는 데 동의하는가. 가칭 「꽃담」 영문명 후보(예: Garden Fence)를 PM이 정해 달라. 조사 A-8상 상표 위험을 팀이 감수할지 여부를 오너 보고에 포함.
3. **캐릭터 구성 확정**: 3번째 캐릭터를 만들지, "꽃"에 그 역할을 맡길지. (제안: 신규 캐릭터 없이 말랑이·토리 + 꽃. 신작에서 둘이 한 판에서 만나게 함.) 에셋 비용과 일관성 부담이 줄어든다.
4. **에셋 예산 확인**: 신작 21장(약 ₩3,056 + 슬라임 스테이지 배경·소품 약 12장 ₩1,800 추정)의 월 사용 허용치와 **이번 달 실제 사용량 확인**(장부가 비어 있어 부정확). Slime 10스테이지의 시간대·섬·소품 신규 장수는 합의된 스테이지 수에 비례.
5. **모션 성능·접근성 규약**: ① 모든 연출에 "움직임 줄이기" 대체안 필수, ② 보상 연출 상한 900ms + 스킵, ③ 44px 규격을 기존 Plop·Acorn 버튼까지 소급(40/36px → 44px)하는 별도 작업을 신작 전에 하는지. 소급을 신작과 함께 하면 일정이 늘고, 안 하면 "통일"이 말뿐이 된다. 이 일정 결정을 PM이 내려 달라.
