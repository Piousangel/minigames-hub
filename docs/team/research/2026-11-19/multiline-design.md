# 말랑 미끄럼길 다중 선 스테이지(5·7·8) UI·모션·지형 시각 스펙

작성: 모바일 게임 UI/모션 디자이너 관점. 저장소 파일은 수정하지 않았다.
근거: opinion-designer.md(토큰·이징·44px), slime-stages-design.md(3장 UX 초안), SlimeProto.tsx, draw.ts, fx.ts, globals.css, useSlimeAudio.ts, 그리고 Playwright 390x844로 /tools/slime-proto 스테이지 6(튕기는 벽)을 직접 본 화면.
한계: ms·px는 "시작값"이다. 프레임 실측·실기 터치 테스트는 안 했다. 효과음은 코드상 파라미터 제안이고 들어보지 못했다. /slime-slide 본 페이지는 열지 않았고 프로토 페이지 UI만 봤다(일일 칩 UI는 코드로만 확인).

## 0. 약점부터 (현재 상태 + 이 제안의 위험)

현재 화면에서 직접 확인한 것:
1. **스테이지 칩 줄이 이미 넘친다.** 390 폭에서 칩 8개(44px x 8 + 간격)가 358px를 넘어 8번 칩이 오른쪽에서 잘려 있다(스크린샷). 5·7·8단계를 쓰려면 8번이 가장 중요한데 잘려 있다.
2. **잉크 막대가 사실상 안 보인다.** 높이 8px, 배경 white/10, 채움 #f4f0ff. 노을 정원 윤곽(3px 갈색)도 없고 선 수 정보를 담을 구조도 아니다. "선 1/2"를 얹으려면 새로 만들어야 한다.
3. **보조 버튼이 정원 규격이 아니다.** "다시 그리기"는 반투명 윤곽 직사각형(어두운 사이트 크롬 스타일), 44px는 지키지만 cream pill·하단 그림자가 없다. "플레임 기록 복사"(개발용)가 주 버튼과 같은 위계로 보인다.
4. **보드 아래 여유가 거의 없다.** 844 기준 보드 하단 y=695, 상태 문구 728, 버튼 752~795, 복사 버튼 816~. 컨트롤 줄 하나(52px)를 더 넣으면 복사 버튼은 확실히 화면 밖이다. 그리고 실제 사파리는 주소창·하단바 때문에 보이는 높이가 약 660~750이다(아래 1-1에서 보드가 얼마나 줄어드는지 계산).
5. **쿠션(튕기는 벽)과 바위의 색 명도가 비슷하다.** 바위 #b98f5e(명도 약 62), 쿠션 #ff7f6b(약 67). 색약에서는 색상 차이가 약해지고 남는 구별 단서는 "점무늬 vs 나이테·풀"뿐이다. 스크린샷에서 쿠션은 노을 하늘(#ff9d7a)과도 같은 난색이라 배경에 묻힌다. 이 문서는 이를 3장에서 보강한다.
6. **START_DELAY가 60스텝(0.5초)이다**(engine.ts). 디자인 토큰은 예비 동작 150ms 이하인데 물리 쪽 정지가 500ms다. 다중 선에서 "시작" 누른 뒤 0.5초 아무 일도 안 일어나면 버튼이 씹힌 것처럼 느껴진다. 엔진을 건드리지 않고 연출로 메우는 안을 4장에 둔다.

이 제안 자체의 위험(5장에 완화책):
- 색·모양·패턴을 중복하다 보면 작은 화면에서 지형이 과밀해진다. 한 스테이지에 새 요소 1종 + 기존 1종 이하 원칙(slime-stages 6장 4번)을 시각에도 적용한다.
- 잉크 막대를 "남은 양 + 선별 사용량"으로 이중 의미로 만들면 오히려 헷갈릴 수 있다. 1단계(막대) 프로토타입에서 5명에게 "지금 몇 % 남았나"만 물어보고 틀리면 단순안(2-2 B안)으로 후퇴한다.

### 1-2. 컨트롤 줄 규격 (358px 폭, 좌우 거터 16)

```
x: 16                                          374
   ┌───────────┐ 8 ┌──────────────────────┐ 8 ┌───────────┐
   │ ↶  Undo   │   │      Start  ▶        │   │ 🗑 Clear  │
   │ 96 x 44   │   │   flex, 최소 150x52  │   │ 96 x 44   │
   └───────────┘   └──────────────────────┘   └───────────┘
   (cream)           (sun-gold, 주 버튼)         (cream)
```
합계 96+8+150+8+96 = 358. 가운데 정렬 보정: Undo/Clear는 세로 중앙(52 줄 안에서 위아래 4px 여백).

| 버튼 | 크기 | 면·윤곽 | 글자 | 비활성 |
|---|---|---|---|---|
| Start ▶ | 150+ x 52 | 면 #ffc933, 윤곽 3px #5b3a1e, 하단 그림자 0 3px 0 #3a2410 | 800 18px #5b3a1e, ▶는 ink 면 삼각형 14px | 선 0개: 면 #f3d9aa 55%, 글자 ink 45%, 그림자 없음. 눌러도 "시작 불가" 반응(아래) |
| Undo | 96 x 44 | 면 #fff3dc, 윤곽 3px ink, 그림자 0 3px 0 ink-deep | 800 14px ink + 아이콘 20px(굽은 화살) | 선 0개: 면 cream 55% |
| Clear | 96 x 44 | 같음 | 아이콘(쓰레기통) 코랄 #e8643f, 글자는 ink(코랄 글자는 대비 3.2:1이라 쓰지 않음) | 선 0개: 55% |

- 위계: Start가 유일한 채워진 주색(황금) + 가장 큼(52 vs 44, 폭 1.6배). Undo·Clear는 같은 크림 보조.
- **Start 선 0개 눌림**: 버튼 가로 흔들림 3회 ±3px 220ms(ease-out-soft), 동시에 보드 위 말랑이 스폰 점선 링이 1회 맥박(scale 1→1.15→1 160ms). 무반응 금지. 소리 `invalid`(기존 SlimeSfx 재사용).
- **눌림 모션**: 모든 버튼 pointerdown 즉시(0ms, transition 없음) translateY(3px) + 그림자 0. pointerup에 spring-jelly로 복귀(220ms, 한 번 오버슈트 -1px). CSS는 `transition: transform 0ms` on :active, `transition: transform 220ms var(--ease-pop)` on release. 터치 후 click이 아니라 pointerdown 시점에 시각을 바꾸고 실행은 click(오터치 취소 가능).
- **Clear 복구**: 전체 지우기 후 Undo 버튼이 3초간 "Restore"(↶ 아이콘 + 라벨 교체)로 바뀌어 직전 선들을 되살린다. 확인 대화상자는 쓰지 않는다(시도를 안 쓰므로 안전하지만 실수 한 번의 손해가 크다는 점은 복구로 푼다). 3초 뒤 또는 새 선을 긋는 순간 복구 불가로 돌아간다.
- 단축키 Z / Esc / Enter(키보드 사용자)는 slime-stages 안 그대로.
- 접근성: 각 버튼 aria-label, 상태 한 줄은 aria-live polite(기존). 선 개수 변화도 같은 줄에 "Line 1 of 2 drawn".

### 1-3. HUD 줄·잉크 줄

HUD 줄(44px): 왼쪽 "Stage 5" 칩(cream pill 44h, 탭하면 스테이지 시트 열기), 오른쪽 소리 44x44. 가운데는 비움(스테이지 이름 문구 금지, 선 정보는 아래 잉크 줄이 담당). 칩 8개 줄은 다중 선 스테이지에서만 접는다(1~4단계는 현행 유지, 스코프 최소화). 다만 칩 줄 8번 잘림 버그는 별도로 수정(칩 간격 6->2px 또는 가로 스크롤 + 현재 칩 자동 중앙 정렬).

잉크 줄(24px, 358폭):
```
 ●  ■     ┌─────────────────────────────────┐  62%
 ①  ②    │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░▒▒▒▒▒▒▒▒▒│
 24 24    └─────────────────────────────────┘  40w
 (핍)      막대 244 x 16, 윤곽 3px ink, radius full
```
- 핍(선 개수): 선 번호 도형 24px. 1번 = 원(cream), 2번 = 둥근 사각(gold), 3번 = 삼각(leaf #7cc26a). 채워진 핍 = 확정된 선, 윤곽만 = 아직 안 그은 선, 핍이 현재 긋는 중이면 맥박(scale 1→1.12, 600ms). 도형이 다르므로 색 없이도 구별. 텍스트 "1/2"는 핍 옆에 쓰지 않는다(공간·언어 비용). 스크린리더에는 aria-label "Line 1 of 2".
- 막대: 트랙 #3a2410(ink-deep). 채움 = 남은 잉크, 색은 **다음에 그을 선의 색**(1번 선 전에는 cream, 1번 확정 후에는 gold). 막대 오른쪽 끝에서 왼쪽으로 **이미 쓴 선별 구간**이 해당 선 색 + 사선 해칭 40% 알파로 쌓인다(소비량이 어느 선에서 났는지). 구간 폭이 20px 이상이면 그 안에 도형 8px 글리프.
- 퍼센트 숫자: 800 14px cream + ink 2px 외곽(사이트 어두운 배경 위에서 가독). 남은 잉크 < 20%: 막대 채움이 코랄 #e8643f로 바뀌고 줄무늬 패턴(색약 대비) + 맥박 1.2s 주기. 0%: 막대 흔들림 120ms, 햅틱 20ms.
- **성능**: 막대 채움은 width가 아니라 `transform: scaleX()` 변경(레이아웃 없음), 갱신은 pointermove 8px 샘플마다가 아니라 rAF 1회.

### 1-4. 엄지 위치와 오터치 방지

원칙: 시작은 "의도 있는 한 번의 탭"이어야 하고, 선 긋기의 끝(손 뗌)과 절대 충돌하지 않아야 한다.

| 위험 | 완화 |
|---|---|
| 손을 떼는 위치가 보드 하단이라 바로 아래 Start와 닿음 | 보드 PlayZone 하단 8%(41px)는 이미 그릴 수 없는 띠 + 프레임 그림자 9 + 간격 12 = **약 62px 완충**. 그리기는 pointer capture라 보드 위에서 시작한 입력은 버튼 클릭이 되지 않는다. |
| 손 뗀 직후의 잔여 터치·손바닥(오른손 엄지 관절)이 Start를 침 | 마지막 선 확정 후 **250ms 동안 Start·Clear 입력 무시**(시각은 눌림 없음, 약 30%만 어두워지는 정도로 미세 표시 금지: 사용자는 모름). 400ms 이상 걸리는 의도 탭에는 영향 없음. |
| 왼손: 엄지가 화면 왼쪽 아래를 돌며 닿음 | Start를 **가운데 폭 150+**로 둔다. 오른손·왼손 모두 가운데는 도달하고, 가장자리 버튼(Undo 왼/Clear 오른)은 한쪽 손에게는 먼 거리다. 사용 빈도는 Undo > Clear이므로 Undo를 왼쪽에 두되 한쪽만 멀어도 358폭 폰에서는 모두 도달 범위 안이다(큰 화면은 조사 못 함). **오른손 전용 좌우 반전 토글은 만들지 않는다**(설정 UI 부담 > 이득, 사용자 데이터가 쌓인 뒤 재검토). |
| Clear(파괴적)가 오른쪽 끝, Start 바로 옆 | Start와 Clear 사이 8px 간격 + Clear는 크림 보조색이라 시선·손 모두 Start보다 덜 끌림. Clear 실수 시 3초 복구(1-2). |
| 두 번 탭(Start 더블탭) | Start 누른 순간부터 재생 종료까지 버튼 비활성(눌림 상태 유지 + 라벨 "Running"). |
| 그리는 손가락이 보드 가장자리를 벗어남 | 그리는 중에는 PlayZone 밖으로 나가도 pointer capture로 선이 계속 이어지고, 구역 밖 좌표는 구역 경계로 클램프(기존 동작을 유지 확인 필요: 코드로는 확인하지 못함). |

## 2. 선의 시각 언어

### 2-1. 선 구별 (노을 정원 팔레트 안)

선은 물리적으로 말랑이가 구르는 "바닥"이므로 지형(바위 #b98f5e)과도 구별돼야 한다. 현재 확정선은 cream(255,243,220) 5px, 윤곽은 없다(코드 280행: strokeStyle cream 0.9, lineWidth 5). 밝은 구름·노을 위에서 윤곽이 없으면 대비가 낮다(스크린샷의 구름 영역 참고). **전 선에 ink 윤곽을 추가**한다.

| 선 | 코어 색 | 윤곽 | 시작 태그 | 끝 캡 | 이유 |
|---|---|---|---|---|---|
| 1번 | cream #fff3dc | ink #5b3a1e 10px(코어 6px) | 원 ① 24px, 면 cream | 둥근 캡 | 현행 색을 그대로 유지(학습 비용 0) |
| 2번 | gold #ffc933 | 동일 | 둥근 사각 ② 24px, 면 gold | 둥근 캡 | 노을 하늘(#ff9d7a)과 가까운 난색이지만 윤곽 10px가 대비를 담당 |
| 3번(8단계) | leaf #7cc26a | 동일 | 삼각 ③ 24px | 둥근 캡 | 풀 섬(#7cc26a 윗면)과 같은 색이라 윤곽·태그 필수. 8단계에서만 |

- 색 외 단서: 태그 도형(원·사각·삼각)이 색약 단서. 잉크 막대의 핍과 같은 도형을 쓴다.
- 구별은 색이 아니라 **도형 태그 + 막대 구간**이 주체고 색은 보조.
- 태그: 선 시작점에서 선 방향 반대쪽으로 14px 떨어진 위치(말랑이 스폰 링과 안 겹치게는 스폰 반경 34 밖이어야 하므로 시작점이 스폰 가까이면 태그를 선 법선 방향으로 18px 이동). 태그는 확정 시에만 나타난다.

### 2-2. 잉크 소비 표현

A안(권장): 1-3의 막대(남은 양 채움 + 선별 사용 구간) + **손가락 둘레 링** + 끝 잉크 방울.
- **손가락 둘레 링**: 터치점 중심 반지름 30px(손가락이 가리지 않는 바깥), 두께 4px, 남은 잉크 비율만큼의 호(270° 최대, 위에서 시계 방향). 색은 다음 선 색, ink 2px 외곽. 그리는 동안만, pointerup 후 120ms 페이드. 이유: 손가락이 보드를 보는 시선을 막으므로 막대(화면 위)까지 시선을 올리지 않아도 된다. 남은 20% 이하에서 호가 코랄로 변하고 끝에서 작은 톱니 모양 줄무늬.
- **끝 잉크 방울**: 선 끝(손가락 아래)에 7px 구슬은 그리는 중에만 보인다. 손 뗄 때 구슬이 아래로 톡 떨어지며(translateY 0->10px, 140ms ease-in-snap, 알파 1->0) 작은 번짐 링(r 6->12, 120ms) 1개. 장식이며 성능 부담 없음(파티클 1개).
- 잉크 0%: 선이 더 늘어나지 않고 끝 구슬이 3개의 작은 방울로 터진다(160ms), 링 코랄 1회 점멸, 햅틱 20ms, 소리 `invalid` 변형(아래 4-5).

B안(후퇴 안): 막대는 단순 "남은 %" 한 색(cream, 다음 선 색 변화 없음) + 핍. 소비 구간 쌓기와 색 프라이밍 제거. 5명 테스트에서 A안 막대를 오해하면 채택.

### 2-3. 그리는 중 vs 확정

| 상태 | 코어 | 윤곽 | 광택 | 끝 |
|---|---|---|---|---|
| 그리는 중("젖은 잉크") | 선 색 85% 알파, 폭 6px | ink 10px 80% 알파 | 위쪽 법선으로 2px 흰 선 60% 알파 | 7px 구슬 + 링 |
| 확정("마른 잉크") | 선 색 100%, 폭 6px | ink 10px 100% | 광택 제거, 대신 아래쪽 1.5px 그림자 선(rgba(58,36,16,0.35)) | 둥근 캡 |

- 굳는 연출 150ms(4-2에서 ms 분해).
- 재생 중: 확정과 같다(말랑이가 지나가면 선이 눌리는 변형은 하지 않음, 성능·충돌 판정 불일치 방지).

### 2-4. 실패 후 고스트와 마지막 선 취소

- 실패 직후(결과 D): 모든 확정선이 **고스트화**(코어 알파 55% + 윤곽 알파 55%, 태그 60%). "지난 시도"라는 표식 + "이 선들은 지금도 유효하다"는 모순을 피하려고 **Undo/Start/Clear가 즉시 활성**이고, 고스트는 **편집 시작(Undo 탭 또는 새 선 긋기 시작)** 하는 순간 남은 선이 100%로 복귀(150ms ease-out-soft). 즉 고스트는 "대기 중 표시"이지 "비활성"이 아니다.
- **궤적 고스트**: 말랑이의 실제 낙하 경로를 점선(ink 35%, 3px, dash 4/6)으로 남기고 끝에 ✕(기존 drawFailMark). 선이 아니라 궤적이라 선과 혼동되지 않는다.
- **마지막 선 취소 모션(Undo)**:
  0ms 탭(눌림 즉시) -> 0~180ms 마지막 선이 **끝에서 시작점 방향으로 감겨 들어간다**(길이에 비례해 140~220ms로 클램프, ease-in-snap), 감기는 끝에 작은 잉크 구슬이 선을 따라 후진 -> 시작점 도달 시 태그가 pop-out(scale 1→0, 80ms) -> 동시에 잉크 막대의 해당 구간 해칭이 사라지며 채움이 늘어남(180ms, ease-out-soft) -> 핍이 윤곽만 있는 모양으로 복귀.
  지운 선의 **잔상**(알파 18%, ink 색 단선 5px)이 새 선 하나를 확정할 때까지 남는다(무엇을 고치는지 비교용). 번잡하면 끈다: 선택 기능, 기본 켜짐, 설정 노출 없음(위험은 5장).
- **Clear 모션**: 모든 선이 동시에 감기며(번호 역순 stagger 40ms) 총 220ms. 동시에 막대 100% 복귀.
- **움직임 줄이기**: 감기는 대신 알파 페이드 120ms. 구슬·링 생략.

## 3. 새 지형 요소 4종 시각 규칙 + 구별 가능성 점검

공통 규칙: ① 윤곽 ink #5b3a1e(큰 오브젝트 4, 중간 3, 작은 것 2px), ② 모양 클래스가 색보다 먼저 구별되어야 함, ③ 상호작용(닿으면 변하는 것)은 접촉 시 반드시 변형·소리·햅틱 중 2개 이상.

### 3-1. 강물 띠 (5단계, 잉크 금지 구역)

| 항목 | 규칙 |
|---|---|
| 형태 | 가로로 긴 띠(영역형). 위 가장자리는 물결(사인 진폭 3px, 파장 28px) |
| 색 | 물 #2f9bb0(명도 낮은 청록) 내부, 위쪽 하이라이트 #8fd8e6. **말랑이 몸 색(jelly-cyan #7fe3ff)과 안 겹치게** 더 어둡고 채도 낮은 청록 |
| 패턴 | 흰 물결 줄(~ ~ 형태 3px, 위상 이동 8px/s 흐름) + **경계 해칭**: 위·아래 가장자리 6px에 ink 사선(45°, 4px 간격). 해칭은 "여기 들어가지 마"의 공통 기호(독꽃·바위에는 해칭을 쓰지 않는다) |
| 금지 아이콘 | 띠 왼쪽 끝 안쪽에 16px **펜 위 사선(금지) 아이콘**(cream 면 + ink 윤곽 + 코랄 사선). 글자 없이 규칙 전달. 띠가 길면 반복하지 않고 한 번만 |
| 색맹 | 색상 대신 명도·패턴·아이콘으로 구별(물결 + 해칭 + 아이콘) |

| 손가락이 띠 건너편에서 새로 시작 | 허용(새 선, 2번). 띠 위에서 시작(touch down in band) 시 선이 시작되지 않고 같은 거부 연출 |
| 말랑이 접촉 | 띠는 공중 아래 물이다. 말랑이가 떨어지면: 0ms 입수 -> 물기둥 6방울(청록) + 링 2개(0, 80ms 간격, 420ms) -> 몸 scale 1->0.6 + 알파 1->0.3(250ms) + 눈 @@ -> 소리 `plunk`(기존 `fell` 재사용 가능) |
| 움직임 줄이기 | 물결 흐름 정지(정적 물결), 거부는 해칭 코랄 색 변화 + 아이콘만(튕김·링 없음) |

### 3-2. 스위치와 문 (7단계)

기존 "별 모양 스위치" 안은 폐기 제안: **별은 이미 수집물(황금 별)**이라 별 모양 스위치는 수집품으로 오인된다. 도토리·별이 아닌 형태를 쓴다.

| 요소 | 규칙 |
|---|---|
| 스위치 | **바닥 발판**(둥근 사각 판 40x14, 지형 위에 얹힘). 면 leaf #7cc26a, 윗면 하이라이트 #b8e8a0, 가운데에 ▼ 글리프(ink 2px, 지면으로 누른다는 뜻). 판 아래 갈색 받침 4px. 높이가 낮고 가로로 넓어 점형(독꽃·꽃 목표)과 모양이 다르다 |
| 눌림 | 접촉 0~60ms 판이 3px 내려감(ease-in-snap) -> 면이 #ffc933(gold)로, ▼ 글리프가 ✓로 바뀜(색+모양) -> 금빛 링 r 0->34(180ms). 한 번 눌리면 유지(영구 눌림) |

| 연결 표시 | 스위치와 문에 같은 작은 글리프(◆ 6px)를 램프·판에 각각 찍음(여러 쌍이 있을 때 대비, 한 스테이지엔 1쌍만이 원칙). 스위치->문 사이 **점선 도관**(ink 30%, 2px)을 보드 위에 옅게 그린다(규칙을 글자 없이 전달) |

| 색맹 | 램프 속 빈/채움 + ▼/✓ 글리프 + 창살 접힘 형태 변화(색 아님) |

| 방향 구별 | 입구 = 안으로 말림 + 어두운 코어 + 보라, 출구 = 밖으로 퍼짐 + 밝은 코어 + 금색. 색 외 단서: 회전 방향·코어 명암·팔 형태 |
| 쿨다운 표시 | 통과 직후 재진입 쿨다운 동안 두 포털이 40% 알파로 흐려지고 쿨다운 끝에 100% 복귀(0.3s 소요) |
| 선과의 관계 | 선은 포털 위에서도 그릴 수 있나? 규칙은 엔진 담당에게 확인 필요. 시각은 그 결정에 맞춰 선이 포털 링 위를 지날 때 포털이 위에 그려짐(레이어 순서: 지형 < 선 < 포털 림 < 말랑이) |
| 밤 하늘 대비 | 8단계는 밤(#3d3170->#241c4a). 보라 소용돌이는 어두운 배경에 묻힐 수 있으므로 **림(cream)이 대비를 담당**하고 보라는 내부 액센트로 한정 |

### 3-4. 5종 구별 점검 (작은 화면: 보드 폭 303px일 때)

| 요소 | 모양 클래스 | 주 색(명도) | 패턴 | 크기(보드 논리 px) | 닿으면 |
|---|---|---|---|---|---|
| 바위 기둥 | 선분형, 두꺼움(14) | tan #b98f5e(62) | 가로 나이테 + 윗면 풀 | 길이 가변 | 정지·구름, 변형 없음 |
| 튕기는 쿠션 | 선분형, **더 두꺼움(18)**·끝 둥글고 숨 쉼 | coral #ff7f6b(67) | 점무늬 | 길이 가변 | 크게 튕김 + (추가) 눌림 변형 |
| 독꽃 | 점형, **식물 실루엣(세로로 긴 62px)** | 보라 | 꽃잎 | 62 높이 | 즉사, 경고 링 |
| 문 | 선분형, 14, **세로 창살** | cream(92) + 램프 | 세로 줄 | 길이 가변 | 정지 + 흔들림 |
| 스위치 | 점형, **납작 판(40x14)** | leaf + gold(켜짐) | ▼/✓ | 40x14 | 눌림 |
| 포털 | 점형, **원형 링 52** | 보라/gold + cream 림 | 소용돌이 | 52 | 순간이동 |
| 강물 띠 | **영역형 띠** | 청록(40) | 물결 + 해칭 | 폭 ≥ 보드 일부 | 선 금지 / 낙하 시 입수 |

판정(내 판단, 실측 전):
- **위험한 쌍 1: 바위 기둥 vs 튕기는 쿠션** (둘 다 선분, 명도 비슷). 색약에서 구별은 폭 차이(14 vs 18)와 패턴(점무늬)뿐이다. **보강: 쿠션 위에 윗면 쪽 쉐브론(^ ^ ^) 줄(ink 2px, 16px 간격)과 하이라이트 #ffc1b3**을 추가하고, 쿠션 윤곽을 ink 4px(바위 3.5px)로 키운다. 그리고 쿠션 면 명도를 올려 #ff9a85(명도 약 73)로 바위와의 명도 차를 벌린다. 노을 하늘 위에서 묻히는 문제는 쿠션 아래 ink 그림자를 더 진하게(rgba(58,36,16,0.35))해 푼다. 이 변경은 이미 출시된 3단계에 영향이므로 별도 PR.
- **위험한 쌍 2: 문 vs 바위 기둥** (둘 다 선분). 문은 밝은 cream 창살 + 램프, 바위는 어두운 tan. 명도 차는 크지만 한 스테이지에 같이 나올 때를 고려해 **7단계에서는 바위 기둥을 문 외에 최소화**(slime-stages 칼날 규칙 "기믹 1 + 이전 1"과 일치).
- **포털 vs 독꽃**: 색(보라)이 겹친다(독꽃도 보라). 구별은 형태(식물 vs 링)와 코어(어둠 vs 꽃). 8단계에 독꽃을 같이 두지 않는 것이 안전. 두려면 포털 입구 색을 청 #3a7bd5로 바꿔 보라 독꽃과 분리(색약에서 청/보라가 비슷해지므로 형태 의존).
- **스위치 vs 도토리·별 수집물**: 스위치는 판 모양 + 땅에 붙음, 수집물은 공중 부유(위아래 bob). 해결 위해 **스위치는 bob 없음, 수집물은 항상 bob 유지**.
- 한 화면에 새 클래스 3종 이상 동시 금지(5·7·8단계 각각 새 요소 1 + 기존 1).

## 4. 모션과 타격감

### 4-1. Start ▶ 누른 순간 (타임라인, 0 = pointerdown)

| ms | 연출 |
|---|---|
| 0 | 버튼 translateY 3px + 그림자 0(즉시, transition 없음) + 소리 `start` + 햅틱 10ms(같은 프레임) |
| 0~80 | 모든 확정선 윤곽 1프레임 cream 플래시(알파 0->1->0, 80ms), 컨트롤 3버튼 55%로 페이드(120ms), Start 라벨 "Running" 교체 |
| 80~200 | 말랑이 예비 동작: 스쿼시 scaleY 0.88 / scaleX 1.1 (120ms, ease-in-snap) |
| 120~500 | **대기 구간(START_DELAY 500ms 메우기)**: 말랑이 몸이 미세 떨림(±1px, 60Hz), 선1->선2 순서로 **빛 줄기**가 선 시작에서 끝으로 흐름(선당 190ms, 합계 380ms). 의미: "시작 전 점검". 엔진은 건드리지 않는다. |
| 500 | 출발, 스쿼시 복귀 spring-jelly(stiffness 220, damping 12), 파티클 먼지 3개(움직임 줄이기 시 1개) |

- 만약 엔진 START_DELAY를 다중 선 스테이지에서 줄일 수 있다면(골든 영향 확인 필요) 500 -> 250ms가 더 좋다. 이 문서는 건드리지 않는 전제.
- 80ms 안에 반응하는 요소: 눌림, 소리, 플래시. 말랑이 반응은 80ms 이후라 "입력 반응"이 아니라 "연출 시작"으로 간주.

### 4-2. 선이 굳는 연출 (손 뗀 순간 = 확정, 총 150ms)

| ms | 연출 |
|---|---|
| 0 | 구슬 낙하 시작(2-2) + 소리 `set`(60ms 짧은 톡) + 햅틱 8ms |
| 0~60 | 선 폭 6->8px로 부풀음(젖은 잉크가 퍼짐, ease-pop) + 광택 선 알파 0.6->0.9 |
| 60~150 | 폭 8->6px 정착, 광택 선 알파 0.9->0, 코어 알파 85->100%, 아래 그림자 선 알파 0->0.35 (마르며 단단해짐) |
| 150 | 시작점 태그(① / ②) pop-in(scale 0->1.15->1, 140ms ease-pop, 이 항목만 150ms 초과 가능) |
| 움직임 줄이기 | 폭 변화 없이 알파 전환만 100ms |

비용: 선 하나를 3개 스트로크 패스(윤곽·코어·광택)로 그린다. 선 3개 x 8px 샘플 점 수십~수백 개라 부담은 작지만, 굳는 150ms 동안만 폭 변화가 생겨 그동안 매 프레임 한 선만 다시 그린다(오프스크린 캐시는 5장).

### 4-3. 지형 접촉 연출 (ms)

| 요소 | 연출 |
|---|---|
| 스위치 | 0 접촉 -> 0~60 판 3px 하강 / 말랑이 squash(0.92) 80ms / 금빛 링 r 0->34 (180ms) / 40ms 문 램프 점등 / 40~240 불꽃이 도관을 따라 이동 / 240~460 문 창살 접힘(위 70%는 100ms 안, 4-3 3-2 참조) / 소리 `door` / 햅틱 12ms. 히트스톱 없음(약타). |
| 닫힌 문 | 0 접촉 -> 창살 흔들림 120ms(±2px) / squash 기존 / 스위치 판 2회 반짝(160ms) / 소리 `thud`(낮은 목관 톡, 120Hz 30ms) |
| 포털 입구 | 0~100 말랑이 scale 1->0.2 + 중심 쪽 회전 180°(ease-in-snap) + 입구 링 플래시(알파 1->0, 120ms) + 파티클 6개 중심으로 흡입(움직임 줄이기 2개) -> 100~160 **빈 구간**(말랑이 없음, 점선 호가 출구로 이동 60ms) -> 160~360 출구에서 scale 0.2->1.15->1 + 회전 360°->0 (ease-pop, 200ms) + 금빛 파티클 5개 바깥 방사 / 소리 `portal` / 햅틱 [10, 40, 15]. 엔진은 순간 이동하므로 시각만 160ms 늦게 나타난다: **말랑이의 시각 위치와 물리 위치가 160ms 어긋나는 구간**이 있고, 이때 입력은 없으므로 문제 없지만 충돌 판정(예: 출구에서 독꽃 접촉)이 시각보다 먼저 일어나면 어색하므로 출구 근처 위험물 배치 금지 규칙(출구 반경 60px 이내 독꽃·문 금지)을 스테이지 설계에 요청 |
| 강물 거부(선) | 3-1 표(0~140ms 튕김, 0~120 해칭 코랄, 60 링) |
| 말랑이 입수 | 3-1 표(0~420ms) |
| 쿠션(기존 3단계) | 코드에서 접촉 연출은 확인 못 했다(squash는 속도 급감에 공통 적용). 제안: 접촉 0ms 쿠션 굵기 18->10px(50ms ease-in-snap) -> 10->20px(120ms spring) -> 18px 정착, 코랄 링 r 0->26(160ms), 소리 `boing`(기존 sfx 재사용 가능 여부 확인). 히트스톱 없음 |

공통: 모든 접촉 연출은 한 번의 타격에 반응 4~6개를 80~100ms 안에 겹침(opinion-designer 1-4). 히트스톱 80~130ms는 쿠션 강타(속도 매우 높음)만 선택 적용 가능하나 이번 범위에서 비권장(플레이 흐름 끊김).

### 4-5. 효과음 4종 (코드 합성, 톤 문서 1-5 규칙: 따뜻한 목관·물방울, 8비트·버저 금지)

기존 SlimeSfx: draw, release, acorn, nest, spiked, fell, stalled, invalid. 새로 필요한 것만 제안(나머지는 재사용).

| 이름 | 용도 | 합성 |
|---|---|---|
| `start` | Start ▶ | sine 380->620Hz 70ms(상승 "뿅") + 5ms 노이즈 클릭, 게인 0.18, 어택 2ms |
| `door` | 스위치 -> 문 열림 | 0ms triangle 300Hz 35ms(톡) -> 40ms bandpass 노이즈 필터 400->900Hz 220ms(나무 문 미끄러짐) -> 250ms sine E5 659Hz 90ms(작은 종), 게인 0.16 |
| `portal` | 포털 | 입구 sine 700->200Hz 100ms(하강 흡입) -> 60ms 침묵 -> 출구 sine 250->900Hz 140ms + 900Hz에 3% 비브라토(상승 방출) + 끝에 sine 1200Hz 25ms 반짝 |
| `reject` | 강물 거부 | 노이즈 로우패스 1.2kHz 50ms(물 튀김) + sine 260->130Hz 120ms(하강, 낮은 "뽀옹"), 버저·사이렌 금지, 게인 0.14 |
추가 `set`(선 굳음): sine 700Hz 25ms + 노이즈 5ms, 게인 0.1. 모든 소리는 연속 재생 시 피치 변주 ±3%로 반복 피로 방지. 음소거와 햅틱은 분리.

## 5. 첫 만남 (튜토리얼 없이, 5단계)

### 5-1. 시퀀스 (보드 진입 = 0ms, 사용자 입력이 없을 때만)

| ms | 연출 |
|---|---|
| 0~400 | 대기(보드 안착, 강물 흐름만 보임) |
| 400 | **손가락 시범**: 40px cream 원(ink 3px 윤곽, 알파 0.9) 말랑이 오른쪽 아래 근처 출발 지점에 120ms 페이드 인 |
| 520 | 누름(scale 0.9, 80ms) + 가상 선 시작(선1 색 40% 알파) |
| 520~1000 | 오른쪽으로 **강 가장자리까지** 이동(480ms, ease-out-soft) |
| 1000 | 가장자리에서 **거부 연출**(3-1과 동일: 해칭 코랄, 튕김, 링, 소리, 햅틱 없음(시범이라) ) |
| 1000~1300 | 손가락이 ±4px 좌우로 흔들림(2회, 180ms) -> 후퇴 |

- 그림은 해법이 아니다: 시범 선은 강 가장자리에서 막히는 짧은 선일 뿐 해법을 보이지 않는다.

- **두 번째 단서**(첫 선을 확정한 순간 1회): 핍 ② 맥박 + 말풍선 "Add a second line, or press Start." (7단어) + Start 버튼 맥박 1회. 이후 영구 숨김.
- 저장: localStorage `slime:seen-river-1`, 읽기·쓰기 모두 try/catch, 실패 시 세션 동안 한 번만 보임. 일일 스테이지 재방문 때는 안 보임.
- 움직임 줄이기: 손가락 이동 생략, 정적 ✕가 있는 강 가장자리 + 정적 화살표 + 같은 문구.

### 5-2. 7·8단계 첫 진입

### 8-4. 타이틀 카드 (스테이지 진입, 0.9초, 스킵 가능)

```
        ┌──────────────────────────┐
        │ (3)  Bouncy Garden       │   <- cream pill, 3px ink 윤곽, 하단 3px ink-deep 그림자
        └──────────────────────────┘      높이 52, 폭 자동(최대 320), 보드 상단에서 26% 지점
         ● 번호 원 32px(gold) + 이름 800 20px ink
```
| ms | 연출 |
|---|---|
| 0 | 진입. 이전 스테이지 하늘 -> 새 하늘 크로스페이드 시작(600ms), 여정 막대의 해·달 아이콘 이동 시작(400ms) |
| 0~180 | 카드 등장: translateY +16 -> 0, scale .92 -> 1, ease-pop. 알파 0 -> 1은 120ms |
| 180~720 | 유지(540ms) |
| 720~900 | 사라짐: translateY 0 -> -8, 알파 1 -> 0, ease-in-snap |
| 합계 | **900ms** |
- **스킵**: 보드는 처음부터 입력 가능(카드는 pointer-events: none). 어디든 pointerdown이면 80ms에 사라짐. 키보드 아무 키도 동일.
- 표시 조건: 스테이지 **처음 진입**과 자동 이동(깬 뒤 3.2초 후)에만. 같은 스테이지 재시도·다시 그리기에서는 안 보임. 하루 첫 진입은 포함.
- 소리: `title` 1개(sine 659Hz -> 784Hz 각 60ms, 게인 0.08). 음소거 시 무음. 햅틱 없음.
- 움직임 줄이기: 슬라이드·스케일 없이 알파 100ms 등장 -> 500ms 유지 -> 100ms 퇴장(총 700ms), 하늘 크로스페이드는 즉시 전환.
- 접근성: 카드 텍스트를 aria-live polite로 한 번 읽음("Stage 3, Bouncy Garden").
- 문구 규칙: 영어 2~3단어. 규칙 설명은 넣지 않는다(5단계 첫 만남 연출이 담당). 이름은 8-2 표.
- 위험: 카드가 보드 위쪽 26%를 가린다. 말랑이 스폰이 보통 y=80~100(보드 위 14~18%)이라 겹치지 않도록 y=26% 고정, 스폰이 그 아래인 스테이지는 카드를 보드 **아래쪽 70%**로 옮긴다(스테이지 데이터에 `titleY` 선택 필드).

- 노드: 터치 영역 44x44(8개 x 44 = 352, 358폭 안에 들어감), 시각은 28px 원. 원 색 = 그 스테이지 하늘 아래색(8-1). 숫자는 ink 800 14px.

## 9. (오너 추가 지시 11-19) 지형 렌더링: 막대기 -> 채워진 덩어리

### 9-1. 현재(진단)
현재 지형은 선분마다 stroke 3겹(그림자 14px, 윤곽 14px #5b3a1e, 몸통 10px #b98f5e)이고 결을 짧은 선으로 그린다(draw.ts drawTerrain). 수평 선분은 별도로 island.webp를 얹는다(drawIslandFloors). 결과: 벽은 14px 갈색 막대, 바닥은 떠 있는 섬 그림이라 스테이지가 "막대 + 판"의 조합이다. 폴리라인 체인을 하나의 모양으로 인식하는 코드가 없다(선분 단위 처리). 이번 제안은 **충돌 데이터는 그대로(선분 체인), 그림만 체인 단위 채움 shape**로 바꾼다.

### 9-2. 데이터와 렌더 분리
- 스테이지에 `landforms`(선택 필드)를 추가하는 안: `{ kind: 'hill'|'island'|'cliff'|'cloud'|'root', chain: Pt[], closeTo: 'bottom'|'under'|'left'|'right', thickness?: number }`. chain의 모든 연속 점 쌍이 `terrain` 선분과 1:1 대응해야 하며 **테스트로 강제**(landform 체인의 선분 = terrain의 부분집합, 어긋나면 빌드 실패). 이렇게 해야 그림과 충돌이 갈라지지 않는다.
- 곡선: 충돌과 그림이 같은 점을 쓰도록 곡선을 **폴리라인으로 먼저 샘플**한다. Catmull-Rom 제어점 -> 선분 길이 12~24px, 정점당 꺾임 각 ≤ 15°. 이유: 엔진은 끝점을 반지름 0 원으로 처리해(types: "끝점은 반지름 0 원과 같이 처리") 큰 꺾임 정점이 말랑이를 튕기는 돌기가 된다. 부드러운 언덕은 꺾임 ≤ 15°면 거의 느껴지지 않는다(엔진 담당 확인 필요, 솔버·게이트가 스테이지별로 확정).
- 그림은 같은 폴리라인을 2차 곡선으로 매끄럽게 이어 채우되 충돌 폴리라인과의 오차가 **1px 이하**가 되게 한다(꺾임 ≤ 15° + 세그먼트 ≥ 12px이면 성립한다고 계산, 측정은 안 함).

### 9-3. 덩어리 그리는 법 (한 체인 = 한 shape)
1. **채움 경로 만들기**: 윗면 = 폴리라인(충돌선). 아래 닫기 방식 3가지.
   - `bottom`(언덕·절벽): 체인 양 끝에서 보드 아래 y=BOARD_H+30까지 수직으로 내려 닫음(프레임에서 잘려 바닥이 안 보임).
   - `side`(벽에 붙은 절벽): 가까운 보드 모서리 밖(x<-30 또는 x>BOARD_W+30)으로 닫음.
   - `under`(떠 있는 섬): 윗면 점 x마다 깊이 d(x) = D·(1 - ((x-xc)/hw)²)^0.6 + 시드 노이즈(±4px)로 둥근 밑면 + 뿌리·종유석 삼각 2~4개. D = clamp(폭 x 0.35, 30, 90).
2. **그리기 순서**(스테이지 안 모든 덩어리 공통): ① 전체 그림자(경로를 (+4,+6) 이동, rgba(58,36,16,0.22)) 일괄 -> ② 윤곽(경로 stroke 4px #5b3a1e, round join) -> ③ 면 채움(세로 그라데이션 아래) -> ④ 지층·돌 질감(경로로 클립) -> ⑤ 윗면 풀 -> ⑥ 가장자리 하이라이트 -> ⑦ 장식(비충돌).
   일괄 그림자를 먼저 그리는 이유: 덩어리마다 그림자를 그리면 인접 덩어리의 면을 그림자가 덮는다.
3. **면 색**: 위 #c79a66 -> 중간 #a97a4a(깊이 40px) -> 아래 #6b4526(깊이 120px, 그리고 40%만 ink 쪽으로). 시간대 바위 틴트(8-1)를 multiply.
4. **지층 질감**(클립 안): 윗면 폴리라인을 18, 40, 72px 아래로 평행 이동한 곡선 3개를 알파 12%(밝은 #ecd0a2 / 어두운 ink 교차)로 stroke, 작은 돌 얼룩 12~30개(시드 고정 = 스테이지 id로 결정적), 균열 3~5개(ink 알파 28%, 길이 10~22px, 윗면에서 아래로). **윗면에서 14px 이내는 질감을 넣지 않는다**(충돌면 읽기 방해 방지, 9-6).
5. **윗면 풀**: 윗면 폴리라인을 안쪽으로 4px 이동한 곡선을 9px #5fbf4a(시간대 풀색)로 stroke, 그 위 1.5px 하이라이트 #9be57e, 풀잎 술(길이 3~7px)은 **경사 ≤ 50°인 구간에서만** 법선 방향으로(시드 간격 11px). 경사 > 50° 구간은 맨 바위(풀 없음). 이것이 "풀 = 서 있을 수 있는 면, 맨 바위 = 가파른 면"이라는 읽기 규칙이 된다(물리 마찰은 같다. 읽기 단서일 뿐이며 과신하면 안 됨).
6. **옆면·절벽면**: 수직에 가까운 구간(경사 > 70°)은 풀 대신 가장자리에 크림 하이라이트 2px(위·왼쪽을 향한 면만), 오른쪽 면은 ink 알파 18% 어둡게(빛이 왼쪽 위에서 온다는 규칙을 모든 덩어리에 통일).
7. **구름 발판**(황혼·별밤): 면 = 크림 #fff3dc -> #f3d9aa 그라데이션, 윤곽 3px ink, 지층 대신 몽글몽글한 호 3~5개(윗면 폴리라인을 따라 반지름 14~22 원호 연속)로 윗면 실루엣. 풀 없음. 바위 덩어리와 **색·질감 모두 다르게** 해서 한눈에 "다른 재질".
8. **뿌리·덩굴**(7·8단계): 윗면 아래로 늘어지는 갈색 곡선(두께 4->1.5px, 길이 20~60px, 끝에 잎 1~2장, 흔들림 사인 ±2px, 느림 3s). 충돌 없음(장식).

### 9-4. 성능·캐시
- 정적 지형은 스테이지 진입 때 **오프스크린 캔버스 1장**(보드 x DPR)에 순서 ①~⑥을 한 번 그려 두고 매 프레임 drawImage 1회로 그린다(현재는 매 프레임 선분 수 x 3 stroke + 결선).
- 오프스크린 크기: 390x560 x DPR 2 = 780x1120(약 3.5MB), 스테이지 전환 때 이전 것 해제. 저사양에서 DPR 상한 2.
- 움직이는 장식(풀 흔들림, 뿌리, 구름 부유)만 별도 레이어에서 매 프레임. 시간대 틴트는 캐시 안에 구워 넣는다(스테이지 = 시간대 고정이므로 문제 없음).
- 움직임 줄이기: 풀 흔들림·뿌리 흔들림 정지.

### 9-6. 막대 모양이 남아도 되는 곳 / 안 되는 곳

원칙: **자연물은 유기적 덩어리, 작동하는 물건은 기하학적 윤곽**. "곡선 덩어리 = 지형, 반듯한 직선·판 = 상호작용 오브젝트"라는 규칙이 곧 어포던스다.

| 구분 | 허용 | 금지 |
|---|---|---|
| 정적 지형 | 위쪽 윗면이 거의 수평인 평지(경사 ≤ 6°, 길이 임의). 단, 반드시 **채워진 고원·섬 덩어리**의 윗면이어야 함 | 두께 14px 갈색 막대로만 이뤄진 벽·바닥. 수직 막대(기둥)는 정적 지형으로 금지: 수직 면은 절벽 면(덩어리의 옆면)으로 |
| 기믹 오브젝트 | 문(창살 막대), 스위치 판, 튕기는 쿠션(버섯 캡 + 선분), 구름 발판 가장자리, 말랑이 선(플레이어) | 기믹이 아닌데 기믹처럼 보이는 반듯한 막대(문과 혼동) |
| 직선 길이 | 정적 지형의 직선 구간 ≤ 60px(곡률·꺾임으로 이어짐), 평지는 예외 | 60px 넘는 비수평 직선 |
| 장식 | 덩굴·뿌리·풀·소나무 등 비충돌 | 충돌면과 같은 면·윤곽을 가진 비충돌 장식(오해 유발) |

### 9-7. 가독성 균형 규칙 (충돌면이 한눈에 보여야 함)

1. **접촉 가장자리 규칙**: 충돌하는 윗면·절벽 면은 항상 ink 윤곽 4px + 안쪽 2px 밝은 림(크림, 빛 방향 면만)을 가진다. 장식은 윤곽 2px 이하, 채도 -25%, 알파 ≤ 70%. 그래서 "굵은 갈색 윤곽 + 밝은 림 = 서는 면"이 전 스테이지 공통 규칙.
2. **텍스트 금지 구역**: 충돌 윗면에서 안쪽 14px, 바깥쪽 24px 안에는 지층 질감·돌 얼룩·균열·덩굴·소나무·반딧불을 두지 않는다(원경 소품 포함). 장식이 말랑이 몸(지름 28)과 겹쳐 길이 안 보이는 일 방지.
3. **대비 하한**: 바위 윗면 윤곽(ink)과 그 바깥 배경의 명도 차 >= 40(8 시간대 하늘 모두), 부족하면 윤곽 바깥에 크림 2px 헤일로(밤·별밤). 시안 8장에서 확인.
4. **말랑이와의 높이 일치**: 말랑이 몸 바닥이 접촉할 때 중심은 선분에서 16px(r14 + 반두께 2) 떨어진다. 그림의 윗면 윤곽 바깥 선이 폴리라인에서 위로 2px에 오도록 정렬. **자동 검사**: 각 스테이지 폴리라인 위 5개 지점에 말랑이를 정지시켜 렌더한 스크린샷의 틈·겹침 <= 2px(스크립트 또는 수식 단언).
5. **디버그 오버레이**: 개발 빌드에서 충돌 폴리라인을 코랄 1px로 겹쳐 그리는 토글(?debug=collide). 그림과 충돌이 어긋나면 즉시 보이게.
6. **재질 = 기능**: 바위(정적, 갈색), 구름(정적, 크림), 쿠션(튕김, 코랄), 문(상태 변화, 크림 창살 + 램프), 위험물(독꽃, 보라)을 항상 같은 재질 언어로. 새 재질 추가 시 3-4 점검표에 먼저 올린다.
7. **원경과 전경 분리**: 원경 실루엣은 채도·대비를 낮추고(알파 35~50%) 충돌 덩어리보다 항상 뒤에 그린다. 원경 능선이 전경 언덕 윗면 높이와 겹치면(같은 높이에 있는 두 곡선) 원경 y를 40px 이상 어긋나게 배치.
8. **작은 화면(보드 303px)**: 질감 알파 15% 이하는 사라지는 것이 정상. 질감 없이도 윗면 윤곽 + 풀/맨 바위 구분이 읽히는지 확인(9-3-5의 경사 규칙).

### 9-8. 새 위험과 구현 영향 (앞 6장에 추가)
- **칼날 위험**: 곡선 언덕은 말랑이를 의도하지 않은 곳으로 보낸다. 디자인이 아니라 솔버·게이트가 스테이지별로 확정해야 한다. 그림 때문에 형태를 바꾸지 말고 **형태를 먼저 확정하고 그 윗면에 그림을 입힌다**.
- **서버 재생 검증**: 폴리라인 점 수가 늘면 스테이지 데이터가 커진다(스테이지당 선분 20~40). 엔진 시뮬 비용은 선분 수에 선형이므로 확인 필요(slime-stages 엔지니어 수치 0.11ms/판 기준 2~3배까지는 문제 없다고 추정).
- **구현 순서에 반영 (7장 PR 재배열)**: 지형 렌더러(9-2~9-4)와 8개 하늘 틴트(8-1)는 엔진과 독립이라 **PR 0으로 맨 앞**에 두는 것을 권장한다. 기존 1~4단계 데이터를 그대로 두고 막대 -> 덩어리 렌더만 먼저 바꿔 시안 8장으로 리뷰한다(충돌 불변이라 골든 테스트 영향 없음, 같은 선분 체인을 그리는 방식만 바뀜). 그 다음 PR 1~5(7장)가 이어진다. 스테이지 8개의 실제 지형 재설계는 솔버·게이트가 필요하므로 스테이지 담당 일정에 맞춘다.
