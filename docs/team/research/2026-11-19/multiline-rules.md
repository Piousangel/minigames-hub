# 말랑 미끄럼길 다중 선 규칙·학습 곡선 확정안 (2026-11-19)

저장소 파일은 수정하지 않았다. 읽은 것: slime-stages-design.md(2~8단계·UX 스펙), SlimeProto.tsx(입력·시도 기록), engine.ts, types.ts, stages.ts, daily.ts, strokePipeline.ts. 엔진은 아래 0장 실험에서만 import로 실행했다(임시 스크립트는 scratchpad에 있고 저장소에는 없다).

## 0. 먼저 허점·위험

**0-1. "선이 많으면 어렵다"는 전제가 틀렸을 수 있다.** 잉크 합계가 같으면 선이 2개일 때 자유도(어디서 끊을지)가 늘어 해가 더 많아지고 무작위 선 성공률도 오를 수 있다. 어려워지는 건 선 개수가 아니라 선이 **제약을 받을 때**(강물 띠 금지, 잉크 한도, 순서)다. 그래서 5~8단계는 "선 2개"를 고정하고 난도는 **다른 축**으로 올린다(2-5). 5단계 게이트에 "길 모르는 무작위 2선 봇 성공률 ≤ 6%"(기존 벽 4%·낮은 벽 3% 수준)를 추가해야 한다. 실측 전이라 통과 여부는 모른다.

**0-2. 선 순서가 물리에 영향을 준다(실측).** 엔진은 선분을 `terrain → lines[0] → lines[1]` 순으로 쌓고 같은 스텝에서 2회 순차 보정한다(engine.ts 25~28행, 충돌 루프). 즉 "모든 선이 동시에 존재"하는 것은 의도일 뿐 수치적으로는 순서 의존이다. 직접 돌려 봤다.
- 무작위 2선 4,000쌍(대부분 서로 안 닿음): 순서를 바꾸면 결과(steps·별)가 달라진 경우 12건(0.3%), 도착 여부가 바뀐 경우 2건.
- 추천 길 + 그 길을 가로지르는 둘째 선 5,843쌍(스테이지 1~4): 달라진 경우 **1,908건(33%)**, 도착 여부가 바뀐 경우 44건(0.75%).
- 같은 선을 2번 겹쳐 그린 4,000건: 결과 변화 0건(겹침 자체는 안전).
→ 선이 서로 닿는 판에서는 순서가 steps를 흔들고 드물게 승패까지 바꾼다. **정준 순서 규칙(3장 규칙 L6)이 없으면 같은 그림이 그린 순서에 따라 다르게 채점**되고 서버 재생이 어긋날 수 있다. 이게 이번 설계에서 가장 큰 빈틈이다.

**0-3. 가만히 재시작하면 같은 결과가 나온다.** 실패 후 선을 유지하는 설계(스펙의 "고스트 유지")는 결정론 엔진에서 **아무것도 안 고치고 시작을 누르면 시도 1회가 헛되이 소모**된다. 시작 버튼을 "직전 시작과 같은 선 집합이면 비활성"으로 막아야 한다(규칙 S4).

**0-4. 시도 기록 시점.** SlimeProto.tsx 431~436행을 보면 시도 기록(`onAttempt`)이 재생이 끝난 뒤에 불린다(추정: 해당 블록이 재생 완료 처리). 재생 중에 탭을 닫으면 시도가 안 세어질 수 있다. 결과가 이미 결정된 상태에서 닫으면 공짜 재시도가 된다. **시작을 누른 순간 기록**해야 한다(규칙 A3). 단일 선 스테이지에도 같은 구멍이 있는지는 [확인 필요].

**0-5. 엔진 수치로 본 "틈으로 새기".** 공 반지름 14, 충돌 거리 D0 16이라 공 중심이 선분에서 16px 안으로 못 들어간다. 두 선의 끝점 사이 간격이 32px 미만이면 공이 못 지나가고, 32px 이상이면 샌다. 탈선이 아니라 정상 물리이므로 규칙으로 막지 않는다(4장 #1). 단 둘이 뾰족하게(약 30° 미만) 만나는 V자 쐐기에서 순차 보정이 공을 반대편으로 밀어낼 가능성은 **측정하지 못했다**. 게이트에 쐐기 퍼즈 테스트를 넣을 것(4장 #2).

## 1. 다중 선 규칙 (확정)

| L5 금지 구역 | 스폰 금지 반경 34px(현행)과 `banZones`(강물 띠)는 **모든 선에 적용**. 시작점이 구역 안이면 거부+링 깜빡임(현행 banNear). 그리는 중 점이나 직전 점과의 선분이 구역에 닿으면 그 점은 버린다(현행 `segmentHitsSpawnBan` 방식을 직사각형 `segmentHitsBanRect`로 일반화). 손가락이 구역 밖으로 나오면 마지막 유효 점부터 이어서 그어진다 | 점만 검사하면 빠르게 그을 때 강물을 가로질러 뛰어넘는다(현행 스폰 반경이 이미 선분 검사로 막은 문제와 같다) |

**시작 버튼을 쓰는 단계(개정: 4~8단계)**: 4~8단계는 `maxLines`가 1이든 2든 모두 시작 버튼 모드(스테이지 필드 `manualStart: true`). 스펙은 "선 1개면 현행"이라 6·7단계(선 1개)가 다시 손 떼면 출발하는 모드로 돌아가는데, 그러면 4→5→6에서 입력 모델이 바뀌어 손이 헷갈린다. 입력 모델 전환은 3→4에서 **한 번만** 일어나야 한다.

**시도 규칙 A (확정)**
- A1 시도 1회 = 시작 버튼 1회 누름. 1~4단계(`manualStart: false`)는 현행대로 손을 떼는 순간.
- A2 시작 후 취소·되돌리기 **불가**. 대신 재생 중 보드 탭으로 **끝까지 건너뛰기**만 허용(결과는 이미 확정이라 영향 없음). 결과가 확정된 뒤 취소를 허용하면 "미리 보기"가 된다.
- A3 시작을 누른 **그 프레임에** 시도를 기록·저장한다(재생 완료를 기다리지 않음). 탭 숨김·이탈·새로고침 후에도 시도는 소진된 상태이고, 돌아오면 결과 화면을 바로 보여 준다.
- A4 실패 후: 그은 선은 **그대로 남고(편집 가능, 연하게 표시)** 공은 스폰으로 복귀, 실패 지점에 ✕ 표시. 선 한 줄만 고쳐 다시 시작할 수 있다. 같은 집합이면 시작 비활성(L10).
- A5 마지막(3번째) 시도에서는 시작이 **2단계**: 첫 탭에서 버튼이 "마지막 기회! 한 번 더" 로 3초간 바뀌고 두 번째 탭이 실제 시작. 모달 없음. 1~2번째는 확인 없음(비용이 작고 확인이 잦으면 짜증).

## 2. 학습 곡선

### 2-1. 5단계에서 "왜 선이 2개인지"를 화면 단서만으로
5단계 보드는 다음 단서만으로 두 선이 필요함을 보인다.
1. 강물 띠가 보드 가로를 가득 채운다(물결 애니, 잉크 금지 구역). 스폰은 강 위쪽 둑, 꽃은 강 건너편.
2. 두 둑의 그릴 수 있는 영역에 희미한 점선 패드와 숫자 **1**(위 둑), **2**(아래 둑)가 있다. 시작 전 잉크 막대에 칸이 2개(● ●)다.
3. 첫 선을 강으로 끌고 가면 손가락이 강 가장자리에서 **멈추고**(선이 더 안 늘어남) 가장자리가 한 번 반짝이며 물결이 퍼진다. 선이 강을 못 건넌다는 걸 직접 체험한다.
4. 선 ①을 확정하면 패드 **2**가 켜진다(깜빡이는 점선).
5. 시작 버튼은 `minLines`(=2)가 채워질 때까지 흐리다. 흐린 버튼 옆 ● ○ 가 "하나 더 필요"를 말한다.
- 이것이 가능한 이유: `minLines = 2`를 솔버가 **증명**했을 때만 쓴다(1선 해가 존재하면 `minLines`는 1이어야 하고 이 단서는 쓰지 않는다). 거짓 단서 방지.
- 한계: 이 구조는 "시작이 흐리다" 자체가 정답 힌트다. 안내문 없이 가르치려면 허용할 수 있는 노출이라고 판단한다.

### 2-2. 첫 10초 안내 문구(영어, 12단어 이내)
- 5단계 진입 직후, 첫 선을 긋기 전에만 표시, 첫 선 확정 시 사라짐: **"Two lines. Water blocks ink. Draw both, then Start."** (8단어)
- 첫 선을 긋고 강에 막혔을 때 한 번: **"Can't draw on water. Use the other bank."** (8단어)
- 6단계 이후: 문구 없음(시작 버튼 라벨 "Start ▶"만).
- 한국어는 현행 언어 설정에 맞춰 동일 뜻으로 번역. 문구는 3초 후 반투명, 보드 밖(잉크 막대 위) 한 줄. localStorage로 "봤음"을 저장하되 실패해도(try/catch) 매번 보여 주는 쪽으로 기본.

### 2-3. 힌트 규칙(다중 선)
- 트리거는 현행과 같다: **연속 2번 실패하면** 3번째 시도 직전에 표시. "연속"은 시작 버튼을 눌러 실패한 시도만 센다(그리다가 지운 것은 세지 않는다).
- 표시: 선 ①②를 **점선 2본**으로 동시 표시, 선마다 같은 번호 칩. 잉크는 소모되지 않는다. 점선은 **자동으로 선이 되지 않는다**. 플레이어가 따라 그어야 한다(현행 단일 선 힌트와 같음).
- 힌트 사용 시도는 `hint: true`로 기록(현행 규칙 유지).
- 위험: 단일 선 추천 길의 σ12 생존율이 약 40~50%(s-bounce 40%)이고 선이 2개면 흔들 변수가 2배라 **따라 그어도 성공률이 더 낮다**. 3번째가 마지막 기회라 5단계가 사실상 0점 통과로 몰릴 수 있다. 게이트 조건을 추가한다: 사람형 봇(σ8)이 힌트 2선을 따라 그었을 때 성공률 ≥ 50%. 못 맞추는 스테이지는 출시하지 않는다. 설계서가 아직 [미확인]으로 둔 값이다.

### 2-4. 실패 원인 표시
시뮬이 돌려주는 `outcome`과 trace만으로 클라이언트에서 판정한다(엔진은 건드리지 않는다).
| 상황 | 표시 |
|---|---|
| 강 위에서 추락 | 낙하 지점 ✕ + "물에 빠짐" |
| 건너편 선에 못 닿음 | 받는 선(②) 쪽이 깜빡이고 "받는 선이 짧았어요" |
| 선 ①만 쓰고 시작(7·8단계, `minLines`가 있으면 불가능하지만 2선 중 하나가 쓸모없을 때) | 안 쓰인 선 흐리게 + "선 2는 닿지 않았어요" |
| 어느 선에도 닿지 않고 추락 | 공이 처음 지나간 구간에 점선 ✕ |
| 스위치·문(7)·포털(8) | 설계서 표를 따른다("문이 닫혀 있었어요", 입구 진입 여부) |
마지막으로 공이 닿은 선 번호는 trace를 선분과 대조해 클라이언트에서 계산한다(엔진 비트 동일 유지, 골든 회귀 영향 없음).

### 2-5. 5~8단계 난도를 "선 개수" 하나로 올리지 않는 법
선 개수는 5·7·8이 **모두 2**로 고정이다. 오르는 축은 단계마다 다르다.
| 단 | 선 | 새 축 | 난도가 오르는 이유 |
|---|---|---|---|
| 5 | 2 | 제약(금지 구역) | 선이 강을 못 건넌다. 앞선은 속도를 만들고 뒷선은 받는다. 잉크 여유 약 1.5배 |
| 6 | 1 | 외력(바람) | 선 개수를 1로 **내려** 공간 지각만 시험한다. 바람 보정을 머리로 계산 |
| 7 | 2 | 순서(스위치→문) | 두 선이 같은 모양이 아니라 서로 다른 역할. 잉크 여유를 5단계보다 **줄인다**(약 1.25배) |
| 8 | 2 | 불연속(포털) | 출구에서의 속도·위치를 미리 계산. 잉크 여유 약 1.15배, 3번째 별이 어려운 위치 |
- 5단계 별 3개는 "선이 2개로 풀리는데 별 3개를 먹으려면 숨은 곡선이 필요"하게 해서 선 개수와 별개로 정밀도를 요구한다.
- 6단계가 1선인 것이 핵심: 선 개수는 단조 증가하지 않는다. 5(2)→6(1)→7(2)→8(2)이므로 "선이 늘었으니 어렵다"는 느낌을 막는다.
- 잉크 여유(= `ink / 솔버 최소 해 잉크`) 곡선: 5단계 1.5, 6단계 1.4, 7단계 1.25, 8단계 1.15. 수치는 설계 목표이고 솔버로 실측해 조정한다.

## 3. 점수·별

- **공식 변경 없음**: 점수 = 별 × 100 + 남긴 잉크 %. 사용 잉크 = **모든 선 길이 합**(파이프라인 후, 0.5px 격자 점으로 서버가 재계산). 최대 이론값은 400이 아니라 299+. 선이 2개면 최소 80px를 써서 잉크 보너스가 구조적으로 100%에 못 간다(단일 선 스테이지도 40px라 100%가 안 나오는 건 동일).
- **선 개수 보너스는 두지 않는다.** 이유: ① 선 개수 보너스는 "1선 숨은 해"를 찾는 보물찾기를 만들고 일일 순위를 한 가지 발견에 몰아준다. ② 잉크 보너스가 이미 경제성을 보상한다. ③ `minLines`가 증명된 스테이지(5·7·8)는 애초에 1선으로 못 푼다. 1선 해가 존재하는 스테이지는 `minLines=1`로 두고 보너스 없이 두면 된다. 숨은 해를 기뻐하게 하려면 점수가 아니라 공유 문구에 칭호(예: "1-line clear")만 붙이는 것은 가능하다(점수 무관).
- **별 3개**: 도토리 3개를 모두 먹고 꽃에 도착. 5단계에서는 도토리 위치가 선 ① 구간, 선 ② 구간에 각각 걸쳐 있어 두 선 모두 쓸 이유를 준다(선 하나만 별 3개를 못 먹게 지형 설계).
- 호환: `scoreOf(outcome, stars, inkUsed, inkMax)`의 `inkUsed`에 합계를 넘기기만 하면 된다. `daily.ts` 수정 없음.

### 서버 재생 검증 입력 형식(제안)
```
POST { v: 2, day: "2026-11-21", stage: "s-river",
  attempts: [
    { n: 1, hint: false, lines: [ [[x2,y2],[x2,y2],...], [[...],...] ] },
    { n: 2, hint: false, lines: [...] },
    { n: 3, hint: true,  lines: [...] }
  ] }
```
- 좌표는 현행 `recs`와 같이 **보드 좌표 ×2 정수**(0.5px 격자). 선 1개 스테이지는 `lines` 길이 1로 호환. 실패 시도도 모두 보낸다(해금 순서·힌트 정당성 검증용).
- 서버 검사: ① `1 ≤ lines.length ≤ maxLines`, `≥ minLines`(미만이면 거부가 아니라 "실패 시도"로 처리) ② 선마다 길이 ≥ 40, 점 간격 ≤ 8.5px ③ **합계 길이 ≤ ink + 0.5×선수**(오차) ④ 스폰 금지 반경·`banZones` 위반 없음 ⑤ 점이 보드 안 ⑥ 선을 L6 정준 정렬 후 `simulate` ⑦ `n`은 1부터 연속, ≤ 3, 앞 스테이지 통과 후만 ⑧ `hint: true`는 앞 2시도가 연속 실패일 때만 ⑨ 같은 선 집합이 연속 시도로 오면 거부(시작 비활성 규칙의 서버 반복) ⑩ 본문 ≤ 32KB(선 2개×시도 3개×스테이지 8개 ≈ 150점×2좌표×… 수십 KB 미만이므로 스테이지별 제출이면 충분).
- 엔진 결과(outcome·별)는 서버가 재계산한 값만 쓴다. 클라이언트가 보낸 점수는 무시.

## 5. 규칙 요약 1페이지 (구현 번호 목록)

**스테이지 데이터**
1. `Stage`에 선택 필드 추가: `maxLines`(기본 1), `minLines`(기본 1, 솔버가 증명한 값만), `manualStart`(기본 false), `banZones: {x0,y0,x1,y1}[]`. 기본값이 있으므로 기존 스테이지 결과는 비트 동일.
2. 단계별 값은 7장 표를 따른다(4단계 2/1, 5단계 2/2+banZones, 6·7단계 1/1, 8단계 2/2, 4~8 모두 manualStart).

**그리기**
3. 한 번에 한 손가락(`activePointer`). 다른 손가락은 무시한다.
4. 선은 40px 미만이면 확정되지 않는다(안내 "too short"). 점은 현행 파이프라인(3px→RDP→Chaikin→8px→0.5 격자)을 선마다 적용한다.
5. 잉크는 합계. 선 k를 그리는 동안 상한 = `ink − 이미 쓴 합 − 40×(minLines − k)`(k는 1부터, 음수면 0).
6. 스폰 금지 반경 34px와 `banZones`는 모든 선에 적용: 시작점이 안이면 거부+깜빡임, 그리는 중에는 점/선분이 구역에 닿으면 그 점을 버리고 밖으로 나오면 이어진다.
7. 선 교차·겹침·기존 선 위 시작 모두 허용.
8. 그리는 동안 시뮬·프리뷰 없음. 공은 스폰에 정지.

**지우기**
9. ↶(Z) 마지막 선 취소, 선 번호 칩 탭으로 그 선 삭제, 전부 지우기(Esc). 모두 무료·확인창 없음·재생 중 비활성·잉크 반환.

**시작·시도**
10. `manualStart` 스테이지: 시작 버튼이 활성이려면 선 ≥ `minLines`, 마지막 포인터 업 후 400ms 경과, 직전 시작과 다른 선 집합(정준 해시), 재생 중 아님, 시도 남음, 로드 때와 같은 날짜를 모두 만족.

13. 시작 후 취소 불가. 재생 중 입력 무시, 보드 탭 = 끝까지 건너뛰기. 탭을 닫아도 시도는 소진.

**힌트**
16. 시작으로 센 시도가 연속 2번 실패하면 선 전체를 점선 + 번호 칩으로 표시(자동 그리기 없음, 잉크 무소모, `hint: true`).

**점수**
17. 점수 = 별 × 100 + 남긴 잉크%, 사용 잉크 = 선 길이 합. 선 개수 보너스 없음.

19. 날짜: 로드 시 `day` 고정, 시작 직전 재확인, 서버는 자정 후 10분까지 전날 제출 수용.

**게이트(출시 전 필수)**
20. 5·7·8단계: 무작위 2선 봇 성공률 ≤ 6%, 힌트 2선 따라 그리기 봇(σ8) 성공률 ≥ 50%, 선 순서 교환·교차 퍼즈 테스트 통과(정준 정렬 후 결과 동일), `minLines` 증명(1선 해가 있으면 1로).

## 6. 오너가 결정해야 할 것 3개

1. **시작 버튼 범위.** 제 권고는 4~8단계만(1~3은 현행 손 떼면 출발). 이유: 신규 방문자의 첫 10초에 버튼 하나를 더 얹지 않는다. 대신 4단계에서 한 번 배우면 8단계까지 같은 모델이다. 반대안은 전 단계 통일(학습은 쉬우나 1단계 이탈 위험이 있고 현재 방문자 수 데이터가 없다). 오너의 "별도 시작 버튼" 요청이 1~4에도 적용되는지 확인이 필요하다.
2. **힌트의 강도.** 5단계는 연속 2번 실패하면 선 2개를 한꺼번에 점선으로 보여 주는데, 이것은 거의 정답 공개이고 따라 그어도 성공률이 낮을 수 있다(2-3). 선택: (a) 점선 2본 전부(제 권고, 0점 통과를 줄임), (b) 선 ①만 먼저 보여 주고 3번째 실패 후 ②는 보지 못함(퍼즐성↑, 0점 통과↑). 일일 점수에서 힌트 사용이 어떻게 표기되는지(현재 `(used a hint)`)도 같이 정해야 한다.
3. **일일 초기화 시각.** 지금은 UTC 자정이라 한국 09:00에 새 일일이 열린다. 한국 사용자에게 의도된 시각인지, KST 자정으로 바꿀지 결정이 필요하다. 바꾸면 `DAILY_EPOCH`와 일 번호·서버 `day` 검증·공유 번호가 모두 바뀌므로 스테이지 번호가 하루 어긋나지 않게 출시 전에 정해야 한다.

# 개정·추가 (오너 지시 11-19: 8개 전부 서로 다른 규칙·풍경, 유기적 지형)

## 7. 8개 스테이지 배치, 선 개수, 난도 곡선, 공유 이름

**배치를 바꾼 이유(점검 (b))**: 기존안은 1~4단계 선 1개 → 5단계에서 **시작 버튼 + 선 2개 + 금지 구역**이 한꺼번에 나온다. 새로 배울 것이 3개라서 급하다. 그래서 **4단계를 징검 단계**로 두고 5단계 강물은 "필수 2선"만 새로 배우게 한다. 5단계의 시작 버튼·두 번째 선이라는 개념은 4단계에서 이미 익힌다. 바람(6→7)·튕김(4→6)은 자리를 옮겼다. 포털은 가장 위험한 기믹이라 8단계에서 빼고 스위치 문으로 바꿨다(포털은 9단계 이후 후보, 설계서 6장 7번의 대체안과 같은 판단).

| 단 | 이름(공유용) | 배우는 규칙 1개 | 선 (max/min) | 시작 버튼 | 지형·풍경 | 난도(1~10, 무작위 선 성공률 기준 추정) |
|---|---|---|---|---|---|---|
| 1 | **1 Slope** | 선은 길이다: 말랑이에서 꽃까지 잇는다 | 1/1 | 손 떼면 출발 | 아침 꽃밭, 완만한 곡선 언덕 두 개와 둥근 꽃 둔덕 | 1 (기존 슬라이드 30%) |
| 2 | **2 Poison Garden** | 독꽃은 닿으면 끝. 선은 휘어도 된다 | 1/1 | 손 떼면 출발 | 한낮 정원, 둥근 바위 섬 위의 독꽃, 곡선 둔덕 | 2 (13%) |
| 3 | **3 Cliff Step** | 벽·계단 턱은 속도로 넘는다(내려가서 올라온다) | 1/1 | 손 떼면 출발 | 노을 절벽, 계단 턱 2~3칸과 곡선 사면 | 4 (3~4%) |
| 4 | **4 Twin Lines** | **시작 버튼**을 누를 때 달린다. 두 번째 선은 **선택**이다 | 2/**1** | 시작 ▶ | 해질녘 두 언덕 사이 골짜기. 별 3번째 도토리는 두 번째 선이 있어야 닿는 위치 | 3 (일부러 낮춤) |
| 5 | **5 River Crossing** | 강물 위에는 잉크를 못 긋는다 → 선 둘이 필요 | 2/**2** | 시작 ▶ | 초저녁 강, 둑 두 개, 징검 바위(곡선) | 5 |
| 6 | **6 Jelly Bounce** | 초록 젤리 면에 닿으면 튕긴다 | 1/1 | 시작 ▶ | 분홍 젤리 동굴, 둥근 젤리 혹 | 6 (무작위 1%, 힌트 사실상 필수) |
| 7 | **7 Wind Canyon** | 구름 띠 안에서는 옆으로 밀린다 | 1/1 | 시작 ▶ | 한낮 협곡, 절벽 사이 바람길 | 6 |
| 8 | **8 Star Gate** | 별 스위치를 지나야 문이 열린다 | 2/2 | 시작 ▶ | 밤, 반딧불, 반원 문 | 8 |

- 선 개수는 **1,1,1,2(선택),2(필수),1,1,2**로 단조 증가가 아니다. 난도는 "규칙의 종류"(입력→제약→외력→순서)와 잉크 여유로 올린다(2-5의 원칙 유지, 1.5→1.15).
- 난도는 4단계에서 **한 번 내려간다**(3→3, 새 입력 모델을 익히는 숨 고르기). 6단계 튕김은 무작위 1%라서 힌트가 필수인 만큼 입력 모델이 안정된 뒤(4·5단계 이후)에 둔다.
- 반전본(`-m`)은 일일에서 제외하고 연습 풀로 보낸다. 1·2·4(=기존 벽)단계 지형을 새로 만든다(새 풍경이 새 해를 만들므로 각 스테이지가 게이트·힌트·강건성 시험을 다시 통과해야 한다. 기존 `STAGE_HINTS`·골든 회귀 항목은 이 스테이지들에 재사용할 수 없다).
- 스테이지는 **끝에만 추가**한다는 `SLIME_STAGES` 규칙과 충돌한다(순서를 새로 정하므로). 출시 전이라면 문제없다. 이미 출시된 날짜의 결과가 있으면 순서 변경은 별도 `v2` 풀로 분리해야 한다.

### 징검 4단계 상세 (점검 (b))
- 4단계는 **첫 선 하나로 반드시 깰 수 있다**(`minLines = 1`). 시작 버튼은 선 1개로도 켜진다.
- 두 번째 선을 유혹하는 법(점수 보너스 없이 물리로): 도토리 ③이 첫 선의 자연 궤적에서 약 60px 벗어난 곳에 있고, 두 번째 선 패드("2")가 그 옆에 있다. 별 3개를 원하는 사람만 쓴다.
- 안내 문구(영어, 12단어 이내, 첫 선 확정 전에만): **"A second line is optional. Press Start when ready."** (9단어)
- 깬 뒤 별이 3개 미만이면 결과 줄 한 줄: **"Try a second line for the last star."** (7단어). 점수에 가산은 없다.
- 4단계에서 시작 버튼 연타·같은 선 집합 비활성·마지막 시도 2단계 확인(L10·A5)을 처음 경험한다. 이후 5단계는 "필수"만 새로 배운다. 5단계 안내문(2-2)은 그대로 쓰되 4단계에서 시작 버튼 설명은 이미 끝났으므로 문구는 "Water blocks ink. Use both banks." (6단어)로 줄인다.
- 점검 결론: 4단계가 없으면 급하다(새 개념 3개 동시). 4단계가 있으면 개념 1개씩이다(입력 → 필수성). 4단계가 지나치게 쉬우면 "두 번째 선이 있는 줄도 모르고 지나갈" 위험이 있다. 그래서 선 패드 "2"와 ● ○ 칸을 4단계부터 항상 보인다.

### 공유 문구에서 단계 구분
현행 공유(`progressShareText`)는 칸 8개 이모지뿐이라 어느 스테이지에서 막혔는지 이름이 없다. 제안:
```
Slime Slide #3 · 5/8 stages · 1,240 pts (used a hint)
1🌟 2⭐ 3⭐ 4🌟 5💥 6⬜ 7⬜ 8⬜
Stuck at 5 River Crossing
```
- `Stage`에 `name`(위 표의 영문 이름) 필드. 이름은 규칙을 직접 말하지 않는 짧은 고유명으로 해서 스포일러가 아니다.
- 모두 깼으면 `Cleared all 8 · best 8 Star Gate`. 시작 버튼 모드 단계의 ⭐가 두 선을 쓴 별 3개인지는 표기하지 않는다(점수 가산이 없으므로).

## 8. 유기적 지형: 선분 근사·통과 폭·끼임 규칙 (오너 지시 2)

### 8-1. 먼저 실측한 것 (엔진 상수 기준)
- 선분은 **두께 0**이고 공 중심이 선분에서 `D0 = 16`(반지름 14 + 반두께 2) 이내로 못 들어간다(engine.ts). 두 지형 사이를 공이 지나려면 **중심선 간격 ≥ 32px**이 물리적 하한이다.
- 곡선을 꺾은선으로 근사하면 오목한 면(골짜기)에서 꼭짓점마다 법선 충돌이 일어나 속도를 잃는다. 실측(`R=140` 원호 그릇, 같은 위치에서 놓았을 때 반대편 오르는 높이, 낙차 105px):
  | 꼭짓점당 꺾임 | 선분 수 | 오른 높이 | 점근값(2°) 대비 |
  |---|---|---|---|
  | 24° | 6 | 45px | 69% |
  | 12° | 13 | 56px | 86% |
  | 8° | 19 | 59px | 91% |
  | 4° | 38 | 63px | 97% |
  | 2° | 76 | 65px | 100% |
  (현재 마찰 계수로는 매끄러운 원도 100% 회복이 아니므로 절대값이 아니라 상대 비교다.) 같은 모양의 곡선도 꺾임이 클수록 느려진다는 뜻이다.

### 8-2. 근사 규칙 (빌더가 강제)
1. **현 오차 ε ≤ 1.5px**(꺾은선과 원래 곡선의 최대 거리). 렌더가 같은 꺾은선(둥근 조인트)이라 눈에 보이는 면 = 충돌 면이다. 눈과 물리가 어긋나는 일이 없다.
2. **오목한 면의 꼭짓점 꺾임 ≤ 12°**(위 표에서 86%). 볼록한 면은 공이 떠나므로 ≤ 20°까지 허용.
3. **선분 길이 10~40px**(권장 16~32). 10px 미만은 순서 의존·떨림을 늘리고 계산만 키운다. 40px 초과는 곡선을 각져 보이게 한다. 곡률 반경 R일 때 길이 `L ≈ 2·sqrt(2·R·ε)`이고 R=100에서 약 35px, 그리고 꺾임 12°면 `L ≤ 0.21·R`이다. 두 조건 중 짧은 쪽을 쓴다.
4. **날카로운 모서리 금지**: 지형 꼭짓점의 **내부각 ≥ 60°**(예각 칼날 금지). 의도한 절벽 끝·계단 모서리는 `corner: true`로 표시하고 외부각 ≤ 90°(내부각 ≥ 90°)만 허용. 직각 계단 턱은 허용한다.
5. **얇은 판(막대) 금지에 가까움**: 닫힌 폴리곤으로 정의하고 최소 폭 24px(공 지름 28 이하의 가는 기둥은 눈에 안 보이는 얇은 칼날이 된다).
6. **끝점 공유**: 인접 선분은 정확히 같은 좌표를 공유한다(0.5px 격자에 스냅 후 비교). 틈이 있으면 32px 미만이라 공이 못 새지만 "틈 규칙"을 지키려고 정확히 일치시킨다.
7. **선분 순서는 경로 순서**로 고정(정점 0→n). 같은 폴리라인을 다른 시작점에서 만들면 0-2의 순서 의존 때문에 결과가 달라질 수 있다. 빌더 출력의 순서를 해시로 고정한다.

### 8-3. 통과 폭·끼임 규칙 (반지름 14 + 16 기준)
- **최소 통과 폭 80px**(서로 다른 지형 사이 중심선 간격). 32px가 물리 하한이므로 80px면 공 지름 2×16=32의 약 2.5배, 한 손가락으로 그은 선이 흔들려도(σ12 기준 약 24px 폭) 통과할 여유가 있다. 설계서가 tier3 좁은 틈을 탈락시킨 이유와 같다.
- **죽은 틈(32~80px) 금지**: 겉보기엔 열려 있는데 물리적으로 겨우 들어가는 틈은 "공이 끼는 틈"이다. 서로 다른 지형 사이 간격이 32~80px이면 오류, 32px 미만이고 눈에 닫혀 보이는 틈(≤ 6px)은 "밀폐"로 병합한다. 6~32px는 오류(시각과 물리가 어긋남).
- **주머니(오목 모서리)**: 공 중심이 들어갈 수 있는 두 면 사이 각 θ에서 공은 꼭짓점에서 `16 / sin(θ/2)` 떨어진 곳에 걸린다. θ < 60°이면 입구 폭이 80px 미만이라도 공이 깊이 들어가 멈춘다(stalled 1초). 해 경로 위의 오목 모서리는 **내부각 ≥ 90°**, 경로 밖 함정은 입구 폭 ≥ 80px면 허용.
- **스폰·꽃·도토리 여유**: 스폰은 지형과 ≥ 50px(스폰 금지 반경 34와 선 두께 여유), 꽃 둥지는 지형과 ≥ 22+16 = 38px 이상 떨어진 평평한 곳 또는 폭 ≥ 80px 그릇 안.
- **터널링**: 최대 속도 800px/s, `DT = 1/120`이면 스텝당 6.7px이고 충돌 두께가 `D0=16`이므로 선분을 뚫을 수 없다(두께 32 대 6.7). 곡선 지형으로 충돌 조건이 늘어도 이 여유는 변하지 않는다.
- **0-2의 순서 문제는 지형 선분 사이에서도 생긴다**: 곡선 한 개가 선분 30~80개이면 꼭짓점 접촉이 더 잦다. 순서를 빌더 해시로 고정하는 이유다(규칙 7).

### 8-4. 솔버·게이트에 미치는 영향과 대응 (오너 지시 2-(c))
| 영향 | 내용 | 대응 |
|---|---|---|
| 계산량 | 충돌 비용은 `스텝 × 2회 × 선분 수`. 현재 스테이지는 선분 3~4개. 곡선 지형은 60~150개, 즉 **20~40배** | 후보 평가 600개×6라운드×k 3~5 = 약 1만 5천~2만 회 시뮬. 선분 수가 늘면 판당 시간이 0.11ms에서 2~4ms로 늘 수 있고, 솔버는 수 초→수십 초, 서버 재생(L1)은 8판 최악 약 30~60ms로 **무료 플랜 CPU 10ms 제한 위험**. **대응**: 선분 AABB 사전 컷(공 반지름+이동 반경 밖은 건너뜀, 비트 동일 유지 가능), 서버는 스테이지별 제출로 쪼갬. 실측 전이다 |

### 8-5. 스테이지 정의 데이터 형식과 빌더·검증 (오너 지시 2-(d))
**형식(제안)**: 런타임 엔진은 지금처럼 `Seg[]`만 쓴다. 사람이 쓰는 정의는 `shapes`에 두고 오프라인 빌더가 `terrain`을 생성한다.
```ts
type Shape =
  | { kind: 'poly';   pts: Pt[]; closed?: boolean; corner?: number[] }          // 꺾은선·닫힌 다각형(꼭짓점 번호별 corner 표시)
  | { kind: 'arc';    c: Pt; r: number; a0: number; a1: number }                // 원호(각도는 도 단위, 빌더에서만 삼각함수)
  | { kind: 'spline'; pts: Pt[]; closed?: boolean; tension?: number }           // Catmull-Rom, 빌더가 ε≤1.5로 분할
  | { kind: 'blob';   c: Pt; rx: number; ry: number; wobble?: number }          // 둥근 바위 섬(닫힌 곡선)
interface StageDef { id: string; name: string; shapes: Shape[]; bouncy?: number[] /* shape 번호 */; banZones?: Rect[]; ... }
```
**빌더(`scripts/slime-build-stage.ts`)**: ① 각 shape를 8-2 규칙으로 꺾은선화(오차 ε, 꺾임 상한을 만족하도록 적응 분할) ② 좌표를 0.5 격자로 스냅 ③ 선분 순서를 경로 순서로 고정 ④ 결과를 `src/lib/games/slime/generated/<id>.json`(숫자 리터럴)로 저장, 정의 해시와 함께 기록. **런타임은 정의를 해석하지 않고 생성 파일만 읽는다**(엔진의 "삼각함수 금지" 규칙은 런타임에 한하므로, 빌더의 `Math.sin`이 만든 값이 환경마다 달라도 커밋된 숫자는 같다).

**자동 검증(`validate`, 빌더가 실패 시 비정상 종료)**
| 검사 | 기준 |
|---|---|
| 자기교차 | 같은 shape 안, 다른 shape 사이 선분 쌍 교차 검사(인접 선분 제외). 있으면 오류 |
| 최소 통과 폭 | 서로 다른 지형(비인접) 선분 쌍의 최소 거리: 32 미만이며 6px 초과면 오류, 32~80이면 오류, 80 이상 통과 |
| 꼭짓점 각 | 내부각 < 60° 오류. 오목 꼭짓점 꺾임 > 12° 오류(`corner` 예외), 볼록 > 20° 경고 |
| 선분 길이 | < 10px 또는 > 40px 경고, 0이면 오류 |
| 중복·순서 | 중복 꼭짓점, 비정규 순서(해시 불일치) 오류 |
| 스폰·꽃·도토리·밤송이 | 지형과의 최소 거리(스폰 ≥ 50, 둥지 ≥ 38, 도토리·밤송이 ≥ 30), 겹침이면 오류 |
| 도달성 | 격자 BFS로 스폰→둥지가 지형·banZones를 피해 연결되는지(연결이 안 되면 선이 절대 못 잇는 판) |
| 선 가능 영역 | 스폰 금지 반경·`banZones`를 뺀 면적이 ink로 그을 만한지(잉크 / 최소 해 길이 ≥ 1.1) |
| 폴리곤 방향 | 닫힌 shape는 한쪽 방향(예: 반시계)으로 정규화, 법선이 바깥을 향하게(공이 안쪽으로 빠지지 않게) |
| 시각 = 물리 | 렌더용 윤곽을 빌더 출력의 같은 꺾은선으로 그림(별도 스플라인 렌더 금지) |

- 새 지형 스테이지의 게이트 순서: 빌더 → validate → 격자 거리장 → 솔버 → 9조합 강건성 → 선 순서 교환·교차 퍼즈 → 힌트 추출 → 골든 항목 추가.
- 이번에 실측하지 못한 것: 선분 수 증가에 따른 시뮬 시간, 12° 규칙에서의 9조합 강건성, 쐐기 퍼즈. 빌더 첫 스테이지(1 Slope)로 이 셋을 먼저 재야 한다.
