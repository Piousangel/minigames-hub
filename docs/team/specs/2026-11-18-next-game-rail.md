# 게임 종료 후 다음 게임 추천 (연결 고리 #3)

## 0. 한 줄 요약
- 사용자가 한 판을 끝내면 지금은 **오버레이의 "Next: 제목" 버튼 1개**(규칙은 "같은 카테고리의 엄선(featured) 게임"이라 사실상 클래식)와, 보드 아래 5번째에 있는 NextUp 카드 1장뿐이다. **클릭 계측이 0**이라 이 연결이 쓰이는지조차 모른다.
- 선택안: **오버레이는 한 줄도 키우지 않고**(버튼 1개 유지, 추천 규칙만 교체 + 계측), **보드 바로 아래에 2장짜리 "다음 게임" 레일**(같은 장르 1·다른 입력 1, 둘 다 오리지널 우선)을 둔다. 게임·캔버스·오버레이·레일 안에 광고는 넣지 않는다.
- 판정은 자체 계측(`next_show`→`next_*` 클릭률) + 목적지 코호트(`?ref=next`). 홈 E1과 화면이 겹치지 않고 태그로 분리된다.

**종합 (근거 한계 포함)**
1. 포털 3곳(Poki·CrazyGames·itch) 모두 **게임오버 후 추천 방식의 공개 근거를 못 찾았다.** 공개된 건 광고 배치뿐이다(#1·#3). "경쟁사는 이렇게 한다"는 주장은 못 한다.
2. 확인된 것: 끝난 직후 화면은 포털이 광고에 쓰는 자리라, **광고 없이 다음 게임을 주는 것**이 차별이 될 수 있다(가설). 사용자 불만은 "강제 이동·광고"(#5)에 몰려 있다.
3. 웹 게이머는 세션에 2~3개를 한다(#2, 보고서 자체 정의). 우리의 현재 연결 지표는 **없다**(아래 2장).

### 2-2. '다음 게임' 고르는 규칙 (`src/components/GameNav.tsx`)
- 제외: 현재 게임·오늘 한 게임·최근 목록(`:46`, `RECENT_KEY`).
- 풀: **같은 카테고리의 featured → 같은 카테고리 전체 → 전체 featured → 전체**(`:53-62`). 선택은 `pool[run % pool.length]`(`:63`) — 세션 RUN으로 회전.
- **문제 1 (코드 확인):** featured는 18개뿐이고 대부분 클래식·인기작이다(gameMeta.ts의 `featured: true` 18줄: 2048·snake·minesweeper·tetris·unblock·beatline 등). 반면 Recoil(`gameMeta.ts:161`)·Lagline(`:158`)·Hunch(`:162`)·FizzBeat(`:163`)·Polarity(`:167`)·Acorn Hop(`:159`)·Plop Landing(`:160`) 에는 `featured`가 **없다**. 그래서 예를 들어 Lagline(Arcade) 다음 추천은 featured Arcade(Snake·Tetris 등 클래식)에 가고, 오너 방향(오리지널이 정체성)과 어긋난다. HeroPlayButton PICKS(`HeroPlayButton.tsx:14-22`)는 이미 오리지널로 바뀌었는데 **끝난 뒤 연결은 아직 클래식 쪽**이다.
- **문제 2:** 카테고리가 4개(Puzzle·Arcade·Classic·Skill, `gameMeta.ts:16`)라 "같은 장르"가 넓다. 조작(`controls`, 113줄 기록)은 있으나 추천에 안 쓴다.
- 추천이 **하나뿐**이라 취향이 안 맞으면 대안이 없다.

### 2-3. 보드 아래 (`src/components/GamePageLayout.tsx`)
순서: 보드(children) → Reactions(`:63`) → GameSwitcher "Jump back to"(최근 6개 아이콘, `:66`·`GameSwitcher.tsx:20`) → GameStats(`:69`) → DailyDock(`:72`) → **NextUp(`:75`, 같은 픽 1장, `NextUp.tsx:12-37`)** → Leaderboard(`:78`) → Comments(`:81`) → 소개 → "Go deeper" 공략(`:96-118`) → 설명·FAQ → CollectionLinks(`:153`) → AdSlot `game-incontent`(`:156`, 현재 렌더 안 됨) → RelatedGames "More games"(`:158`, 같은 카테고리 목록순 6개, `RelatedGames.tsx:13-23`).

- RelatedGames는 목록 앞에서 6개 → 오리지널·신작 가중이 없다(`:15-22`).

### 2-4. 홈에서 다시 시작
홈 FeaturedGames(`page.tsx:105`), MyGames(`:114`), RecentlyPlayed(`:120`) 등. 한 판 끝난 사람이 홈으로 가려면 헤더 로고로 이동해야 하며 **오버레이에 홈·허브 링크는 없다.**

### 2-5. 계측 현황
`grep`으로 `next_click|nextup_click` 코드 사용 **0건**. `hero_play`만 있다(`HeroPlayButton.tsx:32`). `sendHit`은 이벤트 이름 임의(Worker는 20자 slice, hub-connectivity 1장). 도착 태그는 `?ref=<tag>`가 `entryTag`(`hit.ts:29-37`, `^[a-z0-9_-]{1,20}$`)로 blob5에 기록된다 — 새 태그 `next`는 서버 수정 없이 된다.

## 5. 선택안 (C) 기획 v1

### 5-1. 사용자 경험
1. 한 판 종료 → 오버레이는 **지금과 같은 구성**. "▶ Next: …" 버튼의 목적지가 새 규칙의 **'같은 장르' 픽**이 되고 클릭 시 `/${slug}?ref=next`로 이동(자동 이동 없음, 새 탭 없음).
2. 보드 바로 아래(Reactions 다음, GameSwitcher 앞)에 **"Play next" 레일**: 카드 2장(2열, 390px에서도 2열, 각 카드 아이콘·제목·한 줄 이유).
   - 카드 1 **같은 장르**: 이유 `More {Category}` + 오리지널이면 `★ Original`.
   - 카드 2 **다른 입력**: 이유 `{새 조작} instead of {현재 조작}`(예: "Tap instead of arrow keys") + `★ Original`.
   - 이유는 `CONTROL_GLYPH` 라벨(`gameMeta.ts:23-32`)과 카테고리에서 **자동 생성**(110개 큐레이션 불필요).
3. 레일은 항상 보이되(플레이 방해 없는 정적 카드), 종료 시 `next_show`를 1회 보낸다(노출 분모).
4. 기존 NextUp(`GamePageLayout.tsx:75`)은 레일로 **대체**(중복 제거). `data-testid="run-count"`·`aria-label="Next game"`은 유지.

### 5-2. 추천 규칙 (순수 함수 `pickNextGames`, 새 `src/lib/games/nextGame.ts`)
입력: 현재 slug, 오늘 한 게임, 최근 목록, RUN, gameMeta, 오리지널 집합. 출력: `{ same, diff }`(둘 다 없을 수 있음, 서로 달라야 함).
- 제외: 현재·오늘 한 것·최근 8개(기존 `GameNav.tsx:46`과 같음). 후보가 부족하면 최근 제외를 풀고 현재만 제외.
- **같은 장르(same)**: 같은 `category`. 정렬 계층 **오리지널 > featured > 나머지**, 계층 안에서 `run % 길이`로 회전(기존 방식 유지, 결정적·렌더 중 `Math.random` 없음).
- **다른 입력(diff)**: `controls[0]`이 현재와 **다른** 게임(현재에 controls가 없으면 전체). `category`가 현재와 **다르면 가산**. 같은 계층 정렬. same과 중복 금지.
- **오리지널 집합**: gameMeta에 `original` 필드가 없다(60개 여부를 확인 못 함). 우선 **명시 상수** `ORIGINAL_SLUGS`로 시작: owner-direction 5장 명명(Recoil·Lagline·Hunch·FizzBeat·Unblock·Umbra·Bisect) + 최신 오리지널(plop-landing·acorn-hop). 나머지 오리지널은 후속(오너/디자이너 확인 필요).
- 폴백: 오리지널이 후보에 없으면 featured → 나머지. 오리지널이 현재 게임뿐이어도 빈 추천이 나오지 않는다.
- `GameNav`는 `nextSlug/nextTitle`(=same 픽)을 그대로 노출해 `GameOverlay`·기존 테스트와 호환, 새 필드 `picks`·`ended`를 추가.

### 5-3. 지켜야 할 제약
- **광고 금지**: 오버레이·레일·보드 어디에도 `AdSlot`/`ins.adsbygoogle` 없음. 레일은 AdSlot(`GamePageLayout.tsx:156`)과 DOM상 멀리(사이에 6개 이상 블록). (SESSION-GUIDE 0.6 금지, 리서치 #4)
- **오버레이 불변**: 요소·높이를 늘리지 않는다. 변경은 `href`(+`?ref=next`)와 `onClick` 계측뿐(11-17 교훈).
- **다시 하기 우선**: 레일은 보드 **아래**, 오버레이에 겹치지 않는다. 리서치 #6.
- **강제 이동·새 탭·자동 회전 없음**(리서치 #5·#8). 수정키·보조클릭은 `href` 기본 동작(HeroPlayButton 방식, 리뷰 응답 반영).
- 공유 URL·slug 불변(쿼리 `?ref=next`만 추가).

## 8. 사용자 질문 7개 (SESSION-GUIDE '사용자 관점 질문')

1. **처음 온 사람**: 레일 제목 "Play next" + 카드(아이콘·제목·이유 한 줄)는 설명 없이 3초 안에 "눌러서 다음 게임"으로 읽힌다고 본다. 근거는 포털 관행과 현재 오버레이 버튼 문구("Next: …")의 연속성뿐이고 **사용성 시험은 안 했다**(390px 캡처·멍청한 사용 시험으로 구현 때 확인). 첫 10초(레일은 종료 전에도 보임)에 플레이 중 시선을 빼앗지 않도록 정적·저채도로 한다. 신규 방문자는 최근 목록이 비어 추천이 "현재 제외"만으로 정해지므로 낯선 오리지널을 받게 된다 → 리서치 2에서 이탈 위험 확인.
2. **왜 계속 하나**: 끝난 순간의 선택지가 1개→2개(같은 장르 = 익숙함, 다른 입력 = 기분 전환)로 늘고 오리지널 우선이라 사이트 안에 머물 이유가 "이 사이트만의 게임"이 된다. 포털 평균 세션 2~3타이틀(#2)이 참고선이지만 **우리 효과 수치 근거는 없다**(가설). 내일 올 이유는 이 기능 범위 밖(스트릭·데일리 담당). 지루해지는 지점은 다음 주 이후 `next_show` 대비 이동률·`tag=next` 이탈로 본다.
3. **왜 졌나**: 범위 밖(오버레이 결과 정보는 건드리지 않는다). 다만 패배 직후는 감정이 나쁜 순간이라 **다시 하기가 1순위**(리서치 #6)여야 하며 레일이 그걸 가리지 않게 한다. 레일이 "다른 게임으로 도망가라"는 신호로 읽혀 재도전을 줄일 위험은 있다(가드레일 c, 리서치 2).
4. **어떻게 쓰나**: 오버레이 높이 불변(11-17 교훈) + e2e 390px 박스 검증, 카드는 정적·큰 터치 영역(최소 44px 높이 목표), 새 탭·팝업·자동 이동 없음, 수정키 클릭은 기본 링크 동작, 뒤로 가기는 일반 Next 라우팅. 소리 끔·한 손은 영향 없음. 이유 문구는 텍스트(색만으로 구분하지 않음). 탭 숨김·연타는 `next_show` 1회 보장 테스트로 중복 집계만 막는다. 접근성: 카드는 링크(`aria-label`에 제목+이유).
5. **공유**: 범위 밖. 레일은 공유 흐름을 바꾸지 않는다(`?ref=share`·`?vs=` 불변).
6. **우리 사이트에서 왜**: 포털은 이 자리를 광고(부활·미드게임, 리서치 #1·#3)에 쓰고 불만은 그 광고·강제 이동에 몰린다(#5, 일화). 우리는 같은 자리에 광고 없이 오리지널 다음 판을 준다 → 포털에 없는 게임으로 잇는 점이 차별(가설). **포털이 게임오버 후 추천을 어떻게 하는지는 확인 못 함** — 단정하지 않는다.
7. **오너가 볼 때**: 예상 지적 — (a) "레일이 별로 안 눈에 띄는데?" → 모바일 첫 화면 아래일 수 있음, 오버레이 버튼이 보완, 위치 실험 후속. (b) "왜 클래식이 아니라 오리지널만 주나?" → 오너 방향 5장, 단 풀이 9개 상수라 반복될 수 있음(RUN 회전이 있으나 한계). (c) "오리지널 전체를 아나?" → 아니오, 9개만 확인, 나머지는 분류 필요. (d) "효과 수치는?" → 표본이 작아 판정 못 할 수 있다고 미리 문서화(판정 규칙). 먼저 스스로 혹평: 모바일에서 보드가 크면 레일이 안 보여 **계측만 하는 꼴**이 될 수 있다.

## 9. 반증 리서치 2에서 확인할 가정 3개
1. **"끝난 직후 선택지를 늘리면 이동이 늘고 재도전은 줄지 않는다"** — 반증 조사: 게임오버 화면에 다른 게임 추천을 넣어 재시도율·세션 길이가 떨어진 사례(포털·모바일 게임의 end-card 실험, "다시 하기 vs 다른 게임" 충돌, 선택 과부하) 또는 반대로 크로스 프로모션이 세션당 게임 수를 높였다는 근거(숫자·출처·날짜). 근거가 안 나오면 가드레일(c) 강화.
2. **"오리지널 우선 추천은 낯선 게임이라 이탈을 높이지 않는다(또는 높여도 감수할 만하다)"** — 반증 조사: 처음 온 사용자에게 낯선 게임을 추천했을 때의 이탈 근거(콜드 스타트 추천·"익숙함이 재방문에 유리") vs 신작 우대(Poki 신작 2~3주 집중 노출 등). 풀 9개 상수의 품질 근거(품질 감사 상위 5종 외 Umbra·Bisect는 점수 미확인)도 재확인.
3. **"레일을 보드 아래 2번째로 올리면 실제로 보인다(모바일 390px 포함)"** — 반증 조사: 모바일에서 게임 아래 블록의 노출률·스크롤 깊이 근거, 경쟁 사이트가 종료 후 추천을 **오버레이 안**과 **보드 아래** 중 어디에 두는지(접근 가능한 환경에서 포털 직접 열람 — 이번엔 전부 접근 불가), 사용자들의 "추천 품질·광고·강제 이동" 불만을 포털 리뷰·Reddit에서 직접 수집(이번 조사는 일화 1건 수준).

*(보조 확인)* E1과의 지표 분리, 지표 스크립트가 `next_*` 이벤트를 자동 집계하는지, DailyDock 진행도 가시성 저하 여부.

## 12. 기획 v2 (수정점)
1. **계측 추가 `next_seen`**: 레일이 화면에 50% 이상 보인 첫 순간 1회(IntersectionObserver). 가정3을 숫자로 검증 — `next_seen/next_show`가 낮으면 위치 재설계.
2. **낯섦 완화**: 같은 장르 카드가 오리지널이면 '다른 입력' 카드는 **익숙한 featured 클래식**을 먼저(없으면 오리지널). 둘 다 낯선 게임이 되지 않게(가정2). 회귀 테스트로 고정.
3. **재도전 가드레일 강화**: 종료 후 재시작 직접 계측은 아직 없다 → 판정 지표에 "`next_show` 대비 같은 slug의 후속 `view`/종료 수"를 쓰기 어려우므로, 대체 가드레일로 **게임당 종료 신호(finish+win+lose) 수 변화가 출시 전 7일 대비 −20% 넘게 떨어지면 롤백 검토**(표본 작아 추정). 오버레이의 Try again 버튼은 크기·순서·포커스 변경 없음(캡처로 확인).
4. 오버레이는 링크 `href`+`onClick`+노출 계측 외 변경 0(테스트로 고정: `overlay-next-game` 1개, 레일은 오버레이 밖).
5. 오리지널 집합은 컬렉션 `original-games`(27종) + 이후 출시 11종을 합쳐 자동 파생(§5-2의 9개 상수보다 넓다).
6. 판정은 D0+7일, `next_show` n<50이면 연장(D0+14까지). 임계(≥10%/3~10%/<3%)는 추정 그대로.
