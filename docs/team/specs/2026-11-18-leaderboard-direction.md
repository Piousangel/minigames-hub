# 리더보드·경쟁 구조 방향 (오너 11-18) — 허브·샌드랩 공통

> 상태: 방향 확정 + 라운드 1 조사 완료. 라운드 2(반증 리서치) → 기획 v2 → 독립 리뷰 → 구현은 팀이 이어받는다. 조사 원문: `docs/design/leaderboard/R1-hub-audit-and-references.md`, `R1-server-options.md`.

## 오너 방향 (원문 요약)
1. 리더보드 페이지는 **최신 게임 순**으로 보여준다.
2. **랭킹 순위를 더 잘 노출**한다.
3. 이를 통해 **경쟁 심리**를 올린다.
4. **서버 쪽 개발**로 시도할 수 있는 것을 찾는다.
5. 많은 사람이 랭킹에 **몰입하는 구조**, 매일 들어와 게임하게 만든다 → 게임 퀄리티도 계속 발전해야 한다. **샌드랩도 완전히 같은 맥락**(데일리 Spill·레벨별 기록).
오너는 큰 방향만 준다. 세부는 팀이 토론해 정하고(반증·독립 리뷰 포함) 오너에게 묻지 않는다.

## 라운드 1에서 확인된 사실 (조사 요약)
- 허브 `/leaderboards`: 선언 순서(LeaderboardsHub.tsx:30,48)로 게임당 톱3, 최신순 아님(최신순 로직 newGames.ts:29-38은 이미 있음), 빈 보드도 전부 "No scores yet".
- 제출해도 **내 순위를 안 알려준다**(OverlayScoreSubmit.tsx:59-64). 서버는 범위(0~1억)·IP 10초 쿨다운만 검증, 점수는 localStorage 값을 그대로 신뢰, 사용자 식별자·1인 1행 정리 없음. lb_submit 7일 13건(규모 작음).
- 두 제품 모두 **D1 1개 + Analytics Engine 1개**만 사용(KV·DO·R2 없음).
- **비용 위험**: 허브 `GET /api/leaderboards`(worker/index.ts:229-243)가 그 주 전체 행을 읽는다. 주간 1만 행 × 하루 1천 호출이면 D1 무료 읽기(500만 행/일) 초과. → 게임별 LIMIT 3 + 60초 Cache API 캐시가 **가장 먼저 할 서버 작업**.
- 샌드랩 Spill은 CPU 결정적 시뮬(160×240)이고 Replay 포맷이 있어 서버 재시뮬 가능. 틱당 2~6ms(수백 틱 0.5~4초, 2700틱 약 13초) → **Workers 무료 CPU 10ms로는 불가, Workers Paid 필요**. 샌드랩 WebGPU 데일리는 재생 검증 불가. 뿅 착지는 서버 재생 가능해 보이나 CPU 미측정. 비결정적 게임(약 80개)은 게임별 점수 상한·서버 발급 시작 토큰으로 점수/초 검사·상위권 추가 검사·레이트리밋.
- 부수 발견: 허브가 SCORE_SCALE(aim-trainer ×10)을 반영하지 않는 것으로 보임, chess·gomoku·pong이 Wins 리더보드로 등록됨(확인 필요), 허브 레이트리밋 테이블에 **원본 IP 저장**(샌드랩은 해시), `/api/score` 이름에 링크·욕설 필터 없음.

## 확정한 단계 (팀이 라운드 2에서 반증·조정 가능, 단 순서의 이유는 유지)
| 단계 | 내용 | 이유 |
|---|---|---|
| **S0 (1일, 최우선)** | 서버: 리더보드 조회를 게임별 LIMIT + 60초 캐시로, 이름 링크·욕설 필터, 게임별 점수 상한, 레이트리밋 IP 해시화 | 트래픽이 늘면 비용 폭주·어뷰징 위험이 바로 현실이 된다. 사용자 눈에는 안 보이지만 이후 모든 것의 전제 |
| **S1 (1~2일)** | `/api/score` 응답에 rank·total·백분위, 제출 직후 "#N / M · 상위 P%" + 허브 페이지를 **최신 게임 순 + 활성 보드 우선 + 빈 보드 접기** + 측정 이벤트(lb_hub_card_click, lb_board_view, lb_rank_shown, lb_resubmit, lb_challenge_copy) | 오너 방향 ①②③의 최소 구현, 스키마 변경 없이 가능 |
| **S2 (1주)** | 일/주 보드(`best` 테이블+히스토그램), 내 순위 ±N, 서버 발급 익명 player_id, 닉네임 선점, 복구 코드, 도전 링크(?vs=)와 순위 연동 | 경쟁 심리의 핵심: 내 위치·라이벌·지난주 기록 |
| **S3 (1달)** | Workers Paid 전환 판단(비용 승인 필요), Spill·뿅 착지 서버 재시뮬 검증, 시즌 마감 Cron·주간 챔피언 페이지 | 치팅이 실제로 보일 때 투자. 선행 조건: 지표로 필요성 확인 |
가져오지 않는 것(지금 규모): 계정 로그인, Web Push, 시즌 보상, 결제 연동. S3 지표 후 재논의.

## 규칙 (OPERATING 규칙 유지)
- 서버 작업은 **비용·장애 설계·기록 3조건**(DECISIONS 11-16) 충족 후. 유료 전환(Workers Paid)은 오너 결제가 필요하므로 **코드로 시도하지 말고** 필요 시점·금액을 메일로 요청한다.
- 개인정보: 원본 IP·이메일 저장 금지(해시), 닉네임 정책은 Terms에 명시. AdSense 심사 중 큰 구조 변경 금지는 유지(리더보드 UI는 신규 페이지가 아니라 기존 페이지 개편이므로 허용, 구조·라우트 이동은 금지).
- 샌드랩: 같은 구조를 `sandlab` 저장소 `docs/team/specs/2026-11-18-leaderboard-direction.md`에서 이어간다(데일리 Spill 랭킹·레벨별 최단 수·시즌).
- 점수 조작이 의심되는 게임은 리더보드에서 제외 후 보고(삭제는 오너 확인).
