# 오너 방향 11-19(저녁): 말랑 2~8단계 디벨롭 + 신작 확장 + 기존 게임 심화

오너 승인: 세계관 통일('노을 정원') 계속 / 신작 이름 후보로 상표 검색 / 에셋은 스타일 기준·프롬프트를 먼저 확정해 **한 번에 생성** / 서버 재생 검증 진행.

## A. 말랑 미끄럼길 2~8단계를 '좌우만 바뀌는 변주'에서 벗어나게 (최우선)
오너 관찰: 단계가 올라가도 좌우만 바뀌는 느낌. 팀이 고민할 요소(오너 예시):
- **선을 여러 번 긋게 해서 난도 상승**(엔진은 이미 `simulate(stage, lines[])`로 여러 선 지원). 이 경우 **'시작' 버튼을 별도**로 둔다(선 추가·지우기·되돌리기 후 시작).
- **다양한 물리법칙**(바람·얼음·모래·반중력·트램펄린·움직이는 발판 등) — 엔지니어 의견서의 기믹 12종 참고.
- **같은 류 게임 레퍼런스 조사**(선 긋기 물리 퍼즐, 단계가 올라갈 때 새 규칙을 한 개씩 가르치는 방식).
- **디바이스별·가로 풀스크린**: 폰 세로 / 가로 풀스크린 / 태블릿·데스크톱에서 보드가 어떻게 커지고 입력이 달라지는가(스크롤 띠 문제, 풀스크린 API, 방향 고정).
- 산출: 스테이지 2~8 각각의 **새 규칙 1개(배우는 것)**, 난도 곡선, 필요한 엔진·솔버·UI 변경, 시도 구조(스테이지당 3번, 시작 버튼), 일일 슬롯제. 하루 1스테이지 추가 파이프라인(`scripts/slime-add.ts`).

## B. 신작 확장
- **퍼즐형 신작(벽 한 수 퍼즐 / Fence Garden·꽃담 정원)**: 이전 종합 문서 그대로. 착수 전 1일 터치 프로토.
- **데블스 플랜류 게임 더**: Wall Go 하나로 한정하지 않고, 두뇌 대결·규칙 해석형 게임을 우리 방식(1인 퍼즐·일일·AI 약한 상대)으로 재해석. 이름·규칙·그래픽은 베끼지 않는다.
- **앵그리버드류**(새총·물리 파괴) 게임을 **우리 마스코트(말랑이·토리)**로: 장르 규칙은 자유롭게 쓸 수 있으나 **캐릭터·이름·그래픽은 우리 것**. 한 손가락 드래그 발사, 일일 스테이지, 노을 정원 세계.
- 오너 메모: "기존에 만든 게임들을 더 디벨롭할 수도 있고, 할 건 진짜 많다."
