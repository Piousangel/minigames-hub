# Gemini로 퀄리티 올리기 (오너 지시 2026-11-17)

목표: 기본 도형·기본 UI 수준에서 벗어나, **직접 그린 듯한 일관된 비주얼**의 게임을 만든다. 도구는 Gemini(이미지 나노바나나, 화면 평가)이고, 팀은 클라우드 루틴이라 외부 API를 못 부른다. 그래서 **요청 파일 → GitHub Actions가 생성 → main에 커밋** 순서로 쓴다.

## 쓰는 곳
- 새 게임·화면의 **목표 시안**(만들기 전에 완성된 모습을 먼저 뽑는다)
- 캐릭터·오브젝트·아이콘·배경, 공유 이미지(OG), 마케팅 이미지
- **디자인 혹평 리뷰**: 화면 캡처를 Gemini 아트 디렉터에게 보여 주고 약점과 수정 지시를 받는다

## 절차
1. `docs/design/asset-requests/<이름>.json`을 PR로 올린다(형식은 `scripts/gen-assets.py` 머리말). 머지되면 `gen-assets` 워크플로가 만든다.
2. 결과는 `public/art/`(이미지)와 `docs/design/critiques/`(평가)에 main으로 커밋되고 장부 `docs/design/asset-ledger.json`에 기록된다. 다음 PR에서 가져다 쓴다(요청 머지 → 생성 → 사용, 보통 하루).
3. 초안은 기본 모델(`gemini-3.1-flash-image`, 저렴·빠름), **최종 에셋만 `gemini-3-pro-image`**를 쓴다.
4. 프롬프트와 요청 JSON은 지우지 않는다. 같은 스타일로 이어서 뽑으려면 필요하다.

## 퀄리티 규칙 (오너가 지적한 실패에서 나온 것)
- **아트 디렉션 먼저.** 팔레트(5~6색), 외곽선 규칙, 소재 모티프를 문장으로 고정하고, 목표 시안 1장을 `docs/design/<게임>/direction/`에 둔다. 이후 모든 에셋 요청의 `refs`에 그 시안을 넣어 일관성을 유지한다.
- **캐릭터와 나머지가 같은 톤이어야 한다.** 캐릭터만 고급이고 배경·UI가 기본이면 불합격이다.
- **전신 포즈를 통째로 뽑는다.** 부위별 조립(리깅)은 팔이 떨어지고 어색했다. 움직임은 코드의 스프링으로 준다.
- **이미지 안에 글자를 넣지 않는다.** 한글 오타가 난다. 글자는 코드(폰트)로 올린다.
- **배경 제거는 단색 키잉**(`key`). 옷·소품 색과 겹치는 색은 같이 깎인다(민트 옷은 magenta, 분홍·보라는 green).
- **기존 게임·브랜드·실존 캐릭터를 흉내 내지 않는다.** 이름·그림·구도를 그대로 가져오면 안 된다.
- 눈에 보이는 워터마크는 없다. 보이지 않는 SynthID 표식은 들어간다(끌 수 없음, 사용에 영향 없음).
- 에셋은 webp로 최적화되어 나온다. 모바일 첫 화면 총량이 커지지 않게 큰 배경은 `size`를 줄인다.

## 혹평 루프 (새 화면은 PR 전에 한 번)
1. Playwright로 모바일 폭 캡처를 저장소에 올린다.
2. `type: "critique"` 요청으로 평가를 받는다(예시 프롬프트: "까다로운 모바일 캐주얼 게임 아트 디렉터로서 한국어로 혹평: 가장 약한 3가지, 수정 지시, 10점 만점 점수").
3. **6점 미만이면 고쳐서 다시 평가한다.** 평가는 참고이고 최종 판단은 팀이 한다(엉뚱한 지적도 있다).

## 예산
- **오너 11-19 '다 동원해도 좋다'(Gemini·Higgsfield 등 전부)**: 월 600장, 실행당 24장으로 상향(`MAX_PER_MONTH`, `MAX_PER_RUN`). 그래도 '한 번에 제대로' 원칙(스타일 기준·참조 이미지·사전 체크리스트 후 생성)은 그대로.
- (이전) 월 150장, 실행당 12장. 한도에 닿으면 멈추고 다음 실행/달에 이어진다.
- 선불 크레딧을 쓰므로 한도 상향은 오너 승인이 필요하다. 쓸데없이 같은 프롬프트로 여러 장 뽑지 않는다(후보는 한 요청에 3장 이내).

## 요청 예시
```json
[
  {"id": "tori-aim", "refs": ["public/art/tori-idle.webp"], "model": "gemini-3-pro-image", "key": "magenta", "size": 512,
   "prompt": "참조 이미지의 다람쥐 우주비행사를 그대로, 총을 겨눈 자세로 한 장. 단색 마젠타 #FF00FF 배경, 효과 없음, 글자 없음."},
  {"id": "home-critique-1117", "type": "critique", "refs": ["docs/design/shots/home-1117.png"],
   "prompt": "까다로운 모바일 캐주얼 게임 아트 디렉터로서 한국어로 혹평해 주세요. 약점 3가지, 수정 지시, 10점 만점 점수."}
]
```

## 새 게임 출시 체크리스트 (홈 최상단 '최신 출시' 카드)
- 홈 히어로 바로 아래에 **가장 최근 `addedDate`의 게임이 자동으로 큰 카드**로 노출된다(코드 수정 불필요, 오너 지시 2026-11-17).
- 그러므로 새 게임을 낼 때 `gameMeta`에 `addedDate`(UTC)와 **`cover`(16:9, 1200px 안팎 webp, 100KB 이하)** 를 넣는다. 커버는 Gemini로 만든다: 게임 주인공 레퍼런스 + 목표 시안을 refs로, "key art banner, 16:9, 왼쪽 1/3은 비움, 글자 없음". 커버가 없으면 아이콘 카드로 대체되어 밀도가 떨어진다.
- 커버는 모바일 390px 첫 화면에서 잘리지 않는지(제목 오버레이와 겹침) 캡처로 확인한다.

## 비용 규칙 (오너 11-17, 조사: 구독은 API 크레딧이 아님 — 선불 크레딧을 쓴다)
- **단가(11-17 요금표 요약 확인, 환율 ₩1,450)**: pro-image 장당 약 ₩194, flash-image 약 ₩97. 이미지에는 Batch·캐싱 할인이 없다.
- **월 예산 기준 ₩40,000**(오너 승인 방향). 월 상한은 **150장 유지**. 모자라면 팀이 근거(필요 장수·재사용 시도 결과)와 함께 **저녁 요약 메일로 상향을 요청**한다(오너 결정). 잔액 확인·충전은 오너 몫이고, 잔액이 ₩5,000 미만이면 오너가 충전한다(메인 세션이 AI Studio 결제 화면으로 점검).
- **에셋 재사용 우선(가장 큰 절감, 30~40%)**: 구름·섬·꽃·깃발·버튼·HUD·사운드 같은 **공통 요소는 새로 생성하지 말고** `public/art/`의 기존 것을 쓰거나 색조만 바꾼다(코드 틴트). 새 게임의 새 에셋은 **그 게임 고유 캐릭터·소품·커버**에 쓴다.
- **초안은 flash, 최종만 pro.** 같은 프롬프트로 여러 장 뽑지 않는다(후보는 한 요청에 3장 이내). 혹평 리뷰는 시안당 최대 3~4라운드, 점수가 오르지 않으면 에셋을 다시 뽑기 전에 설계부터 의심한다.
- 장부 `docs/design/asset-ledger.json`에 생성 기록을 남긴다(메인 세션이 로컬에서 만든 에셋도 장부에 한 줄 추가). 장부가 비면 사용량을 추정할 수 없다.
