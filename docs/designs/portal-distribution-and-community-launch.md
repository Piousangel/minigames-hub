## Problem Statement

quickminigames.site는 게임 100종을 배포했고 기술적으로 완성돼 있지만 실사용자가 없다.
Cloudflare 대시보드는 하루 100~260 uniques를 보고하나, 자체 beacon(`mg_events`) 기준
실인간은 30일 13명(진단용 vid 2개 제외), **2026-08-21 이후 11일간 0명**이다. 이 격차는
2026-08-10부터 네 차례 같은 방법론으로 재확인됐고, 이번 세션에 처음으로 "센서 고장"
가능성까지 배제했다(아래 Demand Evidence).

문제는 "트래픽이 있는데 전환이 안 된다"가 아니라 **"아무도 사이트를 못 찾는다"**이다.
그리고 3개월간 시도한 해법이 전부 코드였다.

## Demand Evidence

**긍정 증거 — 찾아온 사람은 실제로 오래 즐겼다.**
vid `7ba3d862`가 2026-07-20 ~ 08-12 사이 **8일에 걸쳐 13개 게임**을 플레이했다:
chess 28분 34초 연속 체류, flapjack 24분, gomoku 2분 대국 후 패배, unblock 3연승,
리액션 3건(클릭 필요), 게임 간 내부 링크 이동. 봇이 재현할 수 없는 패턴이다.

이 vid가 사용자 본인이라는 초기 추정은 **반증됐다.** Chrome `visits` 테이블 대조 결과
이 vid의 활동일(7/20·7/21·7/23·8/4·8/5·8/10·8/11·8/12) 중 사용자 실제 브라우저가
사이트를 연 날은 7/23·8/4뿐이고, 가장 활발했던 8/10~8/12엔 방문 기록이 0건이다.
gstack browse 자동 브라우저도 아니다(`.gstack/browse-audit.jsonl`에 7/16·8/4만).

**부정 증거 — 그 사람도 돌아오지 않았고, 아무도 돈을 내지 않았다.**
- 8/12 이후 20일간 재방문 0.
- D1: `scores` 1행(마지막 2026-07-15) · `comments` 1행(8/10) · `reactions` 4행.
- 30일 referrer가 **100% 내부 경로**. 외부 유입(구글·SNS·커뮤니티) referrer가 0건.

**측정 파이프라인은 정상임을 4중으로 증명했다(2026-09-01):**
1. `curl -X POST /api/hit` → 204, 5분 뒤 Analytics Engine 적재 확인.
2. 라이브 번들 `chunks/6727-*.js`에 비콘 코드 포함.
3. `@playwright/test` chromium으로 실제 `/chess` 로드 → `POST /api/hit` 발화, JS 에러 0.
4. 존 로그에서 `/api/hit` 요청이 8/30·8/31 0건, 9/1엔 진단 curl 1건이 정확히 잡힘.

즉 11일 0명은 센서 고장이 아니라 실제 값이다.

## Status Quo

경쟁 대안은 Poki, coolmathgames, CrazyGames, itch.io다. 이들은 이미 검색 결과와
브랜드 인지를 점유하고 있다. 우리 사이트를 찾을 이유가 있는 사람은 현재 존재하지 않는다.

Cloudflare가 "방문자"로 세는 트래픽의 실체(8/30~8/31 상세):
- 요청의 **약 48%가 4xx** — `/wp-admin/install.php`, `/tinyfilemanager.php`,
  `wlwmanifest.xml` 변형 등 PHP/워드프레스 취약점 스캔.
- 8/31 최다 단일 UA = 캐나다발 Chrome/120 104건.
- `iPhone OS 13_2_3` 스푸핑 봇넷이 US/SG/DE/CN/JP/BR/KR/TH 8개국에서 68건.
- SemrushBot, Amazonbot, bingbot, Palo Alto 스캐너.

## Target User & Narrowest Wedge

사용자는 두 세그먼트를 모두 원한다고 답했고(D2), 이는 조건부로 타당하다 —
**두 트랙이 서로 다른 자원을 쓰기 때문이다.**

- **세그먼트 1: 미국 unblocked games 검색자.** DOMAIN.md가 원래 겨냥한 대상.
  추가 코드 작업이 없고 Googlebot이 8/27부터 실제로 크롤 중이므로(Googlebot 13건 +
  Googlebot smartphone 31건 + GoogleOther 9건 + Googlebot-Image 3건) 이 트랙은
  **"하는" 트랙이 아니라 "익는" 트랙**이다. 대기가 유일한 액션이다.
- **세그먼트 2: 한국 고전 보드/퍼즐 유저.** 유일하게 실측된 유저의 프로필과 일치.
  한국어로 직접 글을 쓸 수 있어 유통 비용이 가장 낮고 피드백이 가장 빠르다.

**가장 좁은 웨지: 사이트가 아니라 게임 하나.** 100종을 소개하는 글은 스팸으로 읽히고,
게임 하나를 소개하는 글은 콘텐츠로 읽힌다. 커뮤니티 배포의 단위는 사이트가 아니다.

## Constraints

- 정적 export(Next.js `output: export`) + Cloudflare Workers + D1 + Analytics Engine.
  무계정·엄격 CSP·무료 티어.
- AdSense 승인 상태 "준비 중" — 승인 전엔 사이트 트래픽이 늘어도 광고 수익이 0이다.
- 사용자 시간이 유일한 희소 자원. 계정 가입·본인인증·업로드·커뮤니티 게시는
  에이전트가 대신할 수 없다. 코드 작업량은 제약이 아니다.
- itch.io 템플릿 팩(2026-08-19 완성)의 소스·zip·리스팅 카피는 세션 스크래치패드와
  함께 소실됐다. `node_modules`만 남아 있어 재생성이 필요하다.

## Premises

사용자가 모두 동의했다.

1. **제품은 병목이 아니다.** 유일한 실측 유저가 8일 재방문하고 chess를 28분 했다.
2. **사이트 트래픽을 0에서 의미 있는 수준까지 올리는 건 최소 수개월이고 성공 확률도
   불확실하다.** 기술 SEO는 네 차례 감사에서 고칠 갭을 못 찾았다. 남은 건 대기다.
3. **게임은 사이트와 분리 가능한 독립 자산이다.** 8/19에 3종을 허브 의존성(내비게이션·
   리더보드·후원 넛지·분석 비콘) 전부 제거하고 독립 Vite 프로젝트로 재구성해
   `npm run build` 에러 0 + `vite preview` 200까지 확인했다.
4. **사용자 시간이 진짜 희소 자원이다.** 코드는 무제한, 사용자 저녁은 유한하다.

**EUREKA:** 100종의 게임은 "트래픽 0인 사이트의 콘텐츠"가 아니라 각각 독립적으로
배급 가능한 자산이다. 사람을 우리 사이트로 부르는 대신 이미 사람이 있는 곳으로
게임을 보내면 트래픽 의존성이 사라진다. 이전 세션의 수익화 브레인스토밍(31개 아이디어
→ 3개 렌즈 채점)이 독립적으로 같은 결론에 도달했으나 착수되지 않았다.

## Approaches Considered

### Approach A: 포털 배급에 올인
사용자의 첫 저녁을 itch.io/GameDistribution 계정 가입과 업로드에 쓴다.
- Effort: human 저녁 2-3회 / CC 8-12시간. Risk: Med.
- 사이트 트래픽 0이어도 수익 가능한 유일한 경로. 다만 포털 심사 통과가 불확실하고
  피드백 루프가 수주 단위다. 계정 가입·본인인증·세금정보 입력 잡무가 많다.

### Approach B: 한국 커뮤니티에 올인
사용자의 첫 저녁을 한글 랜딩 검수와 국내 커뮤니티 배포에 쓴다.
- Effort: human 저녁 1회 / CC 2-3시간. Risk: Low, 상한도 낮음.
- 가장 빠른 피드백이지만 "사이트로 사람을 데려온다"는 검증 안 된 가정 위에 있고,
  AdSense 미승인 상태라 사람이 와도 당장 수익이 안 된다.

### Approach C: 병렬 (선택됨)
사용자는 B를, 에이전트는 A의 코드 준비를 동시에. 미국 SEO는 백그라운드로 익힌다.
- Effort: human 저녁 1회 + 다음 주 업로드 1회 / CC 4-6시간. Risk: Low.
- 두 트랙이 서로 다른 자원을 쓰므로 "둘 다"라는 답을 손해 없이 지킬 수 있다.

## Recommended Approach

**Approach C.** 선택 근거: 병목이 사용자 시간이고 A와 B는 그 시간을 서로 다른 시점에
쓴다. 에이전트 작업량은 선택 기준이 아니므로, 코드로 끝나는 A의 준비 작업을 미루는 건
순수한 손실이다. B는 1주 안에 신호가 나오므로 다음 판단의 근거가 된다.

## 실행 계획

### 에이전트 트랙 (사용자 시간 0)
1. **itch.io 템플릿 팩 재생성.** Reactor/Flywheel/Countcircle 3종 + 공용 셸을 독립
   Vite+React+TS+Tailwind v4 프로젝트로 재구성. 8/19에 성공한 절차를 반복하되
   **산출물을 스크래치패드가 아니라 레포 안(`packages/template-pack/`)에 둔다** —
   소실 재발 방지. `npm run build` 에러 0 + `vite preview` 200으로 검증.
2. **리스팅 카피 재작성**(제목/설명/가격/태그) + 스크린샷 5장 자동 촬영.
3. **홈·카테고리 페이지 비콘 추가.** 현재 `sendHit`은 `GamePageLayout`의 `RecordPlay`
   에서만 발화해 홈만 보고 나간 방문자가 측정되지 않는다. 커뮤니티 배포 효과를
   재려면 이 사각지대를 먼저 없애야 한다. 이건 캠페인의 계측 인프라다.
4. **GameDistribution/GameMonetize 제출용 빌드** 준비(포털 규격 확인 후).

### 사용자 트랙 (저녁 1회)
1. 게임 하나를 고른다(자신 있는 것 하나. 사이트 전체가 아니다).
2. 한국 커뮤니티 한 곳에 게임 소개 글을 올린다.
3. 다음 날 `mg_events` referrer로 몇 명이 왔는지 센다.

## Open Questions

- **한글화 범위.** 유일한 실측 한국 유저는 영어 사이트에서 8일을 놀았다. 한글 랜딩이
  실제로 전환을 올리는지는 미검증. 커뮤니티 배포 1회 결과를 보고 정하는 게 맞다.
  선제 한글화는 검증 안 된 가정에 코드를 쓰는 것이다.
- **어느 커뮤니티인가.** 사용자가 직접 고르는 게 맞다(계정·평판·글쓰기 톤을 아는 건
  사용자다). 에이전트는 초안 작성만 도울 수 있다.
- **포털 심사 기준.** GameDistribution/GameMonetize의 현재 제출 요건을 확인하지 않았다.
  계정 가입이 선행돼야 실제 요건을 볼 수 있다.
- **AdSense "준비 중"이 몇 주째인가.** 8/13 확인 이후 재확인 안 됨. 사용자만 볼 수 있다.

## Success Criteria

- **1주 (커뮤니티 트랙):** 외부 referrer가 붙은 실인간 vid가 **1명 이상**. 지난 30일
  외부 referrer가 0건이므로 1명도 질적 변화다. 10명 이상이면 그 채널을 반복한다.
- **1개월 (포털 트랙):** itch.io 리스팅 1건 게시 완료 + GameDistribution 제출 1건.
  판매/수익 여부보다 "제출까지 갔다"가 이 단계의 기준이다.
- **판단 기준:** 두 트랙 모두 1개월 후 신호가 0이면, 그때는 "유통을 시도했는데 안 됐다"가
  검증된 사실이 된다. 지금은 아직 가설이다.

## Distribution Plan

사이트 자체는 기존 파이프라인(`pnpm run deploy` → Cloudflare Workers)이 처리한다.
새 산출물인 템플릿 팩의 배포 경로는 itch.io 수동 업로드(사용자)이며, 빌드 산출물은
레포 `packages/template-pack/`에 커밋해 세션 간 소실을 막는다.

## Dependencies

- itch.io / GameDistribution / GameMonetize 계정 — 사용자 가입 필요(에이전트 불가).
- 홈 비콘 추가가 커뮤니티 캠페인 측정의 선행 조건. 배포 글 올리기 전에 끝나야 한다.
- AdSense 승인은 어느 트랙의 블로커도 아니다(포털 수익은 AdSense와 무관).

## The Assignment

**이번 주 안에, 만든 게임 중 가장 자신 있는 하나를 골라 한국 커뮤니티 한 곳에 직접
올려라.** 사이트 홍보 글이 아니라 게임 하나 소개 글로. 다음 날 `mg_events`의 referrer를
확인해서 몇 명이 실제로 들어왔는지 세라.

이게 중요한 이유: 지난 30일 외부 referrer가 정확히 0건이다. 이 사이트는 아직 단 한 번도
외부에서 사람이 유입된 적이 없다. "홍보하면 사람이 오는가"는 3개월째 한 번도
테스트되지 않은 가설이고, 저녁 한 번이면 답이 나온다.

## What I noticed about how you think

- "본인 아닌데 나 최근에 들어간적없음" — 이 한 줄이 세션의 결론을 바꿨다. 나는 35뷰
  5일짜리 vid를 개발자 본인으로 단정했고, 당신이 그걸 부정해서 Chrome 방문기록을
  대조했고, 그 결과 **이 사이트 최초의 진짜 리텐션 유저**를 찾아냈다. 데이터를 읽는
  사람이 틀렸을 때 반박하는 건 드문 습관이다.
- "둘 다 타겟하고싶은데 ㅠ"라고 답했다. 보통 이건 초점을 못 잡은 신호로 읽히지만,
  이 경우엔 실제로 맞는 답이었다 — 두 트랙이 서로 다른 자원을 쓰기 때문이다.
  틀린 이유로 맞은 게 아니라, 당신이 이미 SEO가 대기 트랙이라는 걸 알고 있었다.
- 3개월간 게임 100종을 만들면서 DOMAIN.md에 경쟁사 검증 패턴을 축적했다. 문제는
  실행력이나 취향이 아니다. 만드는 능력과 알리는 능력이 다른 근육이라는 것뿐이다.
