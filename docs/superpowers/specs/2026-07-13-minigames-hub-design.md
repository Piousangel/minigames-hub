# 미니게임 허브 — 설계 스펙

- 날짜: 2026-07-13
- 상태: 사용자 승인 대기
- 코드네임: `minigames-hub` (브랜드명·도메인은 M1 첫 작업에서 확정 — 아래 §7)

## 1. 목표와 성공 기준

- **목표**: 광고 수익 월 5~10만원(≈ $40~75)을 내는 글로벌 영어 미니게임 웹사이트.
- **수익 산식**: 디스플레이 광고 RPM $1.5~2.5 가정 → 월 3~6만 페이지뷰 필요. 즉 이 프로젝트의 본질은 게임 개발이 아니라 **검색 트래픽 확보**다.
- **기간·리듬**: 주말 사이드(주 5~10시간), 6개월 내 목표 도달.
- **예산**: 도메인비 연 ~2만원이 유일한 고정비. 호스팅·인프라 무료 티어.
- **성공 기준(M6)**: 일 1,000~2,000뷰, AdSense(또는 상위 네트워크) 월 $40+.

## 2. 전략 (승인된 방향)

**접근 A(단일 허브) + C 한 스푼(데일리 게임 1종)**:

- 도메인 하나에 브랜드 있는 게임 허브. 게임을 매주 쌓아 도메인 권위를 누적.
- 콘텐츠 전략 = **클래식 클론 + 니치 변형 롱테일**. 검색량이 검증된 게임(2048, snake, minesweeper 등)을 만들되, 테마 변형 페이지(`2048 animals` 류)로 경쟁 약한 롱테일 키워드를 잡는다.
- 허브 게임 중 1종은 데일리형(매일 바뀌는 퍼즐)으로 만들어 SEO 유입을 재방문자로 전환.
- 기각한 대안: 마이크로 니치 사이트 다수(도메인비·승인 중복, thin-site 리스크), 데일리 원툴(발견이 순전히 바이럴 운).

## 3. 기술 스택 & 아키텍처

- **Next.js(App Router) + TypeScript + Tailwind. 전 페이지 SSG. Vercel 무료 티어.**
- 백엔드·DB 없음. 점수/진행상태는 localStorage. (데일리 게임의 "오늘의 퍼즐"도 날짜 기반 시드로 클라이언트 계산 — 서버 불필요)
- **엔진/테마 분리 원칙**: 게임 로직은 `lib/games/<game>/engine.ts` 순수 TS 모듈(UI 무관, 단위 테스트 대상). 테마는 config 객체. 변형 페이지 1개 추가 = config 1개 + 콘텐츠 텍스트.
- 게임 1개 = 라우트 1개 (`/2048`, `/2048-animals`, `/snake` — 루트 평면 구조, 키워드가 URL에 그대로).
- 페이지 공통: 정적 metadata, JSON-LD(VideoGame), OG 이미지, sitemap.xml 자동 생성.
- **계측(1일차 필수)**: GA4 + Google Search Console. 이후 모든 콘텐츠 의사결정은 GSC 노출 데이터 기반.
- **비주얼 디자인은 클로드 디자인 파이프라인 사용**: `design-consultation`으로 사이트 디자인 시스템(폰트·컬러·레이아웃) 확정 → 필요 시 `design-shotgun`으로 시안 비교. 피그마·외부 디자이너 없음.

## 4. 게임 라인업

### Phase 1 — 런칭 5종 (M1)

| 게임 | 선정 이유 |
|---|---|
| 2048 (테마 시스템 내장) | 변형 롱테일의 본체 |
| Snake | 클래식 대량 검색 |
| Minesweeper | 클래식, 체류시간 김 |
| Memory Match | 저난이도, 캐주얼/키즈 |
| Typing Speed Test | 도구성 — 재방문·체류 높음 |

### Phase 2 — 변형 양산 (M2~)

- 2048 테마 5~10종(동물·디저트·우주 등 자체 제작 테마), Snake 모드 변형.
- **모든 게임 페이지에 300~500단어 텍스트**(How to play / Strategy & Tips / FAQ) — SEO와 AdSense 승인 방어 겸용.

### Phase 3 — 데일리 게임 1종 (M3)

- 매일 바뀌는 단어 또는 숫자 퍼즐(Wordle류 메커니즘, 이름·에셋 완전 자체).
- 이모지 그리드 결과 공유 버튼 포함(재방문 + 바이럴 장치).

### 상표 규칙 (하드 룰)

- 게임플레이 규칙은 보호 대상이 아니나 **원작 이름·에셋 사용 금지**: "Wordle", "Tetris" 등 상표명을 게임명·URL·메타에 쓰지 않는다.
- 테트리스류는 장르 자체를 회피(권리사가 소송에 적극적).
- 사용 키워드는 비상표 일반명(2048, snake, minesweeper, memory game, typing test).

## 5. SEO & 트래픽 계획

- 온페이지: 게임이 뷰포트 첫 화면에서 즉시 플레이 가능, LCP 최적화, 타이틀 패턴 `Play <게임> Online — Free, No Download`.
- 초기 백링크 시딩: Reddit(r/WebGames 등) 소개 포스트, 웹게임 디렉토리 소수, 데일리 게임 출시 시 HN/커뮤니티 1회. 스팸성 대량 등록 금지.
- 예상 곡선: M1~2 ≈ 0 → M3~4 롱테일 변형부터 노출 → M5~6 일 1,000~2,000뷰.

## 6. 수익화 단계

1. **M1: 광고 없음.** 게임 ~10개 + About/Privacy/Contact/이용약관 페이지 완비 후 AdSense 신청(M2). 게임 사이트는 "low value content" 거절이 흔함 — §4의 페이지별 텍스트가 방어책. 거절 시 콘텐츠 보강 후 재신청(횟수 제한 없음).
2. **승인 후 광고 배치(최소주의)**: 게임 영역 아래 1 + 데스크톱 사이드레일 1 + 모바일 앵커 1. 게임 위 배치 금지 — 체류시간 하락은 SEO 악화로 되돌아온다. CLS 방지(광고 슬롯 높이 예약).
3. **월 1만 뷰 돌파 시**: Ezoic 등 미드티어 네트워크 전환 검토(RPM 2~3배). "5만원 사이트"→"10만원+ 사이트" 레버.

## 7. 로드맵 (주말 리듬)

- **M1**: 도메인·브랜드명 확정(첫 작업) → 스캐폴드 + 디자인 시스템(design-consultation) → 게임 5종 + 필수 페이지 → GSC 등록·sitemap 제출.
- **M2**: 2048 변형 ~10종 + 게임 2~3종 추가 → AdSense 신청 → 커뮤니티 시딩 시작.
- **M3**: 데일리 게임 출시 + HN/Reddit 소개. **체크포인트: 일 100뷰 미만이면 키워드 전략 재검토.**
- **M4~6**: 데이터 주도 운영 — GSC에서 노출 발생한 키워드 주변 변형 추가, 죽은 페이지 개선, 1만 뷰 돌파 시 광고 네트워크 상향.

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| AdSense 거절 | 페이지별 텍스트 + 필수 페이지 완비, 보강 후 재신청 |
| SEO 무반응 | M3 체크포인트에서 GSC 데이터로 판단, 매몰비용 최소화 |
| 상표권 | §4 하드 룰 준수 |
| 광고가 UX·SEO 훼손 | §6 최소주의 배치 + CLS 예약 |

## 9. 테스트·품질

- 게임 엔진(순수 TS)은 단위 테스트 필수 — 이동/병합/승리·패배 판정 등 규칙 로직.
- UI는 게임별 스모크 E2E(로드 → 첫 조작 → 상태 변화 확인) 1개씩.
- Lighthouse 성능 예산: 게임 페이지 모바일 LCP < 2.5s.
